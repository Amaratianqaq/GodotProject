# 07 · 樱花霰弹枪实现说明

> `scripts/weapons/cherry_shotgun.gd` —— 第一阶段**唯一**有完整独立实现的武器，
> 也是「怎么给一把武器写专属机制」的参考模板。

## 1. 原型与定位

**原型**：《元气骑士》樱花霰弹枪（橙色 · 传奇）。
**本项目定位**：森林地图「射手」路线的最终武器，近距离爆发全游戏最高。

| 属性 | 值 |
|---|---|
| 品质 | 橙色 · 传奇（`GameEnums.Rarity.LEGENDARY`） |
| 类型 | `WeaponKind.SHOTGUN` |
| 单枚花瓣伤害 | **4.5** |
| 花瓣数 | **5**（技能树「樱花精通」后 6） |
| 单发理论满命中 | **22.5**（满命中 27.0） |
| 散布 | 34°（樱花精通后 27.2°） |
| 射速 | 0.62s/发 |
| 弹匣 / 换弹 | 6 发 / 1.5s |
| 能量消耗 | 4 / 发 |
| 花瓣初速 / 存活 | 215 px/s / 0.62s（射程短，逼你贴脸） |
| 暴击加成 | +5% |
| 屏幕震动 | 1.4 |

## 2. 五个机制，逐个拆解

### 机制一 · 五瓣散射：中心密、边缘疏

```gdscript
func _petal_direction(i: int, count: int, spread_rad: float) -> Vector2:
    var t := (float(i) / float(count - 1)) * 2.0 - 1.0     # -1 .. 1
    var shaped := sin(t * PI * 0.5) * 0.82 + t * 0.18      # ← 关键：sin 压缩
    var jitter := randf_range(-0.035, 0.035)
    var swing := sin(float(_shot_index) * 1.7) * 0.02      # 每发整体左右摆动
    return aim_direction.rotated(shaped * spread_rad * 0.5 + jitter + swing)
```

**为什么要 `sin` 压缩而不是均匀分布**：
均匀分布（`t * spread/2`）会让 5 瓣等距排开，中间有空隙，
近距离贴脸时可能只有 3 瓣命中 —— 霰弹枪「贴脸最强」的直觉就不成立了。
`sin(t·π/2)` 把中间的 t 值压向 0，形成**中心密、边缘疏**：
近距离几乎全部命中（22.5 全中），远距离自然散开。

`jitter` 让每发不完全相同（避免机械感）；
`swing` 让连续射击时的整体偏置缓慢左右摆（视觉上有「扫射」感）。

> **数值含义**：4.5 × 5 = 22.5，对比蓝装秘银弓单发 12、橙装烈焰之刃单发 22 ——
> 贴脸一发 ≈ 一把传说近战的一刀，但射程只有约 133px（215 × 0.62）。
> 这就是「贴身输出 ↔ 保持身位」的取舍来源。

### 机制二 · 花瓣弹墙

```gdscript
pd.max_bounces = 1                  # 可弹墙一次
pd.bounce_damping = 0.88            # 弹后速度保留 88%
pd.bounce_damage_keep = 0.75        # 弹后伤害保留 75%
pd.lifetime = 0.62                  # 总存活时间不变 → 弹墙延长了实际射程
```

`Projectile._bounce_off()` 用 `_estimate_wall_normal()` 做点查询估计墙面法线，
然后 `direction.bounce(normal)`，并 `_hit_ids.clear()`（弹墙后可以再打同一目标一次）。

**手感意义**：走廊、墙角、窄门都能打输出；玩家可以「打墙蹭怪」。
这是原作樱花霰弹枪最有辨识度的特性之一。

### 机制三 · 后坐力顶退

```gdscript
const RECOIL_IMPULSE := 55.0        # 像素/秒
const RECOIL_COOLDOWN := 0.12       # 防止每帧叠加

func _apply_recoil() -> void:
    if _recoil_lock > 0.0:
        return
    _recoil_lock = RECOIL_COOLDOWN
    holder.apply_knockback(-aim_direction * RECOIL_IMPULSE)
    holder.set_z_height(1.5)        # 轻微上抛，体现 2.5D 高度轴
```

连续射击会把玩家往后顶。**这是设计意图**：它强迫玩家在
「贴脸打满 5 瓣」和「被顶出射程」之间做节奏控制，而不是无脑按住左键。

`_recoil_lock` 限制施加频率（0.12s），避免高射速时叠加成瞬间位移。

### 机制四 · 表现堆料（打击感）

| 表现 | 实现 |
|---|---|
| 枪口火焰 | `CombatFx.muzzle_flash(self, mp, aim, 1.35)`（比默认大 35%） |
| 花瓣炸开 | `CombatFx.spawn_sprite_burst(..., 6+2 片, 粉色, 42.0)` |
| 枪身抖动 | `create_tween()` 让 rotation 在 0.13s 内回正 |
| 屏幕震动 | `EventBus.screen_shake_requested.emit(1.4, 0.12)` |
| 暴击提示 | 暴击时额外 `CombatFx.popup("暴击!")` |
| 花瓣拖尾 | `pd.trail_length = 5`（投射物自己生成） |
| 命中特效 | `pd.hit_vfx = &"petal"` → 4 片小花瓣爆散 |
| 换弹光晕 | `_reload_glow` 程序化生成的 24×24 樱花粉光晕，强度随换弹进度 `sin(t·π)` |
| 换弹抖动 | scale (0.88,1.12) → (1,1) 的压缩回弹 |

> 光晕贴图是**代码生成**的（`_make_glow_texture()`），不依赖额外美术资源。
> 这是本项目处理「小装饰性特效」的惯用手法。

### 机制五 · 技能树联动（标签系统示范）

这是**全局技能树影响具体武器**的参考实现：

```gdscript
func _pellet_count() -> int:
    var n := maxi(1, data.projectile_count)
    if SkillTreeService and SkillTreeService.has_tag("cherry_mastery"):
        n += MASTERY_EXTRA_PELLETS          # +1 → 6 瓣
    return n

func _effective_spread() -> float:
    var deg := data.spread_deg
    if SkillTreeService and SkillTreeService.has_tag("cherry_mastery"):
        deg *= (1.0 - MASTERY_SPREAD_TIGHTEN)   # 收紧 20%
    return deg_to_rad(deg)
```

技能树节点 `f_cherry`「樱花精通」的 `granted_tags = ["cherry_mastery"]`。
**武器不关心谁给了标签，只问「有没有」** —— 这样后续加装备/增益/角色被动
都能复用同一套标签查询，不需要改武器代码。

## 3. 与基类的分工

| 谁做 | 什么 |
|---|---|
| `WeaponBase` | 冷却、弹药、能量扣除、后坐偏移、换弹计时、`fired` 信号、`can_fire` 判定 |
| `WeaponCherryShotgun._do_fire()` | **只负责**：掷暴击 → 生成 N 个花瓣 → 播表现 → 施加后坐力 |
| `WeaponCherryShotgun._process()` | 后坐力冷却计时 + 换弹光晕动画 |
| `WeaponCherryShotgun._do_reload_start()` | 换弹抖动 + 音效 |

**没有覆写** `try_fire()` / `consume_shot()` / `start_reload()` —— 那些是基类的职责。

## 5. 用这把枪当模板写新武器

假设要给「烈焰之刃」写专属机制（燃烧 DoT）：

```gdscript
class_name WeaponFlameBrand
extends WeaponBase
## 烈焰之刃：命中附加 3 秒燃烧，每秒造成 30% 武器伤害。

const BURN_DURATION := 3.0
const BURN_DPS_RATIO := 0.30
const BURN_TICK := 0.5

## attacker_instance_id -> {timer, dps}
var _burning: Dictionary = {}
var _tick_accum := 0.0


func _do_fire() -> void:
    var crit := roll_crit()
    var info := build_damage(data.damage, crit)
    info.knockback = aim_direction * data.knockback
    info.tags.append("melee")
    _activate_hitbox(info, crit)
    _play_swing_visual()      # 也可以像 WeaponMelee 那样抄一份
    _play_fire_sfx()


func _activate_hitbox(info: DamageInfo, crit: bool) -> void:
    var hb := _get_melee_hitbox()
    if hb == null:
        return
    hb.set_faction(_faction())
    hb.knockback_force = data.knockback
    hb.hit_landed.connect(_on_hit_landed)     # ← 记录被点燃的目标
    hb.activate(data.melee_swing_time, info.amount, crit)


func _on_hit_landed(target: Node2D, _info: DamageInfo, _dmg: float) -> void:
    if target == null or not is_instance_valid(target):
        return
    _burning[target.get_instance_id()] = {
        "node": target,
        "timer": BURN_DURATION,
        "dps": data.damage * BURN_DPS_RATIO * damage_multiplier(),
    }


func _process(delta: float) -> void:
    super._process(delta)
    _tick_accum += delta
    if _tick_accum < BURN_TICK:
        return
    _tick_accum = 0.0
    for key in _burning.keys():
        var e: Dictionary = _burning[key]
        e["timer"] = float(e["timer"]) - BURN_TICK
        var node: Node = e["node"]
        if e["timer"] <= 0.0 or node == null or not is_instance_valid(node):
            _burning.erase(key)
            continue
        var hb := node.find_child("Hurtbox", true, false) as HurtboxComponent
        if hb == null:
            continue
        var dot := DamageInfo.make(float(e["dps"]) * BURN_TICK, self, holder, _faction())
        dot.tags.append("burn")
        dot.hitstop = 0.0                 # 持续伤害不要触发顿帧
        dot.can_be_blocked = false        # 无视受击无敌帧
        hb.receive_hit(dot)
```

然后：
1. 保存为 `scripts/weapons/flame_brand.gd`
2. 把 `data/weapons/flame_brand.tres` 的 `script_path` 指向它
3. **注意品质计数规则**：`flame_brand` 变成「有专属实现」后会从
   「每品质 3 把通用武器」里被排除 → 需要新增一把橙色通用武器补位，
   否则 `Validation.tscn` 会报「品质「传奇」通用武器数量 2（应为 3）」
4. 跑 `--import` → `Validation.tscn` → `SmokeTest.tscn`

### 写新武器时必须遵守的四条
1. `extends WeaponBase` 并实现 `_do_fire()`
2. **不要**覆写 `try_fire` / `consume_shot` / `start_reload`
   —— 冷却与资源是基类职责，覆写会导致「一次射击扣两次弹」这类 bug
3. 伤害必须走 `build_damage()`（它会乘全局伤害倍率与暴击倍率）
4. 表现走 `CombatFx.*`，不要自己 `new Label/Sprite2D`
