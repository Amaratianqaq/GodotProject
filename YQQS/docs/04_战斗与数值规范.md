# 04 · 战斗与数值规范

> 本文定义**一次伤害从产生到结算到表现**的完整链路。
> 任何战斗相关的改动都必须能对应到下面某一个环节，不允许跳过环节自己算。

---

## 1. 伤害数据包 DamageInfo

`scripts/core/damage_info.gd` —— 战斗系统里**唯一**的伤害载体。

| 字段 | 说明 |
|---|---|
| `amount` | 结算前基础伤害 |
| `damage_type` | `PHYSICAL / ENERGY / POISON / FIRE / TRUE` |
| `source` | 直接来源节点（武器 / 投射物） |
| `attacker` | 归属角色（用于统计与仇恨） |
| `faction` | 来源阵营，**决定友军伤害** |
| `knockback` | 击退向量（已含力度） |
| `crit` | 是否暴击（**在攻击方算好**，防守方不重算） |
| `pierce_armor` | 无视护甲 |
| `can_be_blocked` | 是否可被无敌帧/格挡挡下 |
| `hit_position` / `hit_direction` | 命中点与方向（特效、血方向） |
| `tags` | `"melee" / "bullet" / "petal" / "shotgun" / "cherry" / "enemy_projectile"` |
| `hitstop` | 命中顿帧时长（秒） |
| `screen_shake` | 屏幕震动强度 |

**铁律**
1. 造成伤害必须构造 `DamageInfo` 并通过 `HurtboxComponent.receive_hit()` 传递。
   **禁止**任何地方直接改 `vitals.hp`。
2. 一次命中多个目标时必须 `duplicate_info()`，不要复用同一实例
   （否则第二个目标会拿到被改过的数据）。
3. `crit` 由攻击方决定。原因见 §4。

## 2. 伤害结算管线（唯一实现：`VitalsComponent.apply_damage`）

```
① 死亡检查            _dead → 直接返回 0
② 主动无敌             invincible == true（翻滚等）→ 返回 0
③ 受击无敌             invincible_time > 0 且 info.can_be_blocked → 返回 0
④ 伤害减免             raw = amount × (1 − damage_reduction)     上限 95%
⑤ 护甲吸收             pierce_armor 为假且 armor > 0：
                          absorbed = min(armor, raw); armor -= absorbed; raw -= absorbed
⑥ 生命扣除             raw > 0：hp -= raw
⑦ 状态与广播           清空脱战计时、给受击无敌、emit damaged、
                       损伤顿帧请求、屏幕震动请求
⑧ 死亡                 hp <= 0 → _die()（只发一次 died 信号）
```

调平衡时改的是 **`damage_reduction` / `armor` / `max_hp`**，
而不是去动这段顺序 —— 顺序是战斗手感的一部分。

### 受击无敌帧（i-frame）

| 对象 | 时长 | 为什么 |
|---|---|---|
| **玩家** | **0.55s**（`VitalsComponent.PLAYER_IFRAME`） | 没有无敌帧的话，BOSS 的 12 发环形弹幕会瞬间秒杀玩家 |
| **敌人** | **0s** | 必须为 0，否则「一发霰弹 5 瓣全中」只会算 1 次伤害，霰弹枪的核心玩法就消失了 |

> 敌人的接触伤害盒用 `multi_hit = true, multi_hit_interval = 0.65` 来控制
> 「贴脸持续掉血」的节奏（0.65s 一次，略大于玩家的 0.55s 无敌，所以接触伤害不会被无敌帧吃掉）。

`Actor.invincible`（布尔量）用于**主动**无敌（翻滚/冲刺），与受击无敌独立。
`RogueRoll` 在翻滚期间设 `vitals.invincible = true`，结束时置回 false。

## 3. 命中判定：Hitbox / Hurtbox

```
攻击方                                      防守方
HitboxComponent (Area2D)  ──── overlap ───▶  HurtboxComponent (Area2D)
   layer = PLAYER_HITBOX / ENEMY_HITBOX        layer  = PLAYER_HURTBOX / ENEMY_HURTBOX
   mask  = 对方 HURTBOX | WORLD                mask   = 0（只在被检测，不主动检测）
```

### 攻击盒（HitboxComponent）
- **开关式**：`activate(duration)` 打开，到期自动关闭。**不要常驻开启**，否则擦身即伤。
- 同一次激活内同一目标只结算一次（`_hit_targets` 去重）→ 近战多段判定的基础。
- `multi_hit = true` + `multi_hit_interval` 可做持续伤害区（敌人接触伤害）。
- 伤害不在这里算暴击；调用方通过 `activate(duration, damage, crit, mult)` 传入。

### 受击盒（HurtboxComponent）
- 每个可受伤实体 **有且只有一个**。
- `receive_hit(info)` 做三件事：阵营判定 → 无敌判定 → 转交 `vitals.apply_damage()`。
- 返回**实际造成的伤害**（0 = 被闪避/免疫/同阵营）。调用方用它决定要不要播特效。

### 阵营判定
`info.faction == NEUTRAL` 时谁都打得到；否则 `info.faction != 本盒 faction` 才命中。
这样**攻击方不需要自己判阵营**。

## 4. 暴击

**在攻击方掷骰一次，结果写进 `DamageInfo.crit`，防守方不再重算。**

`WeaponBase.roll_crit()` 的优先级：

```
1. holder.consume_guaranteed_crit()   ← 游侠翻滚后的「必定暴击」窗口，一次性消费
2. WeaponData.crit_bonus              ← 武器自带暴击加成
3. GameState.get_crit_chance()        ← 角色基础 10% + 技能树
4. holder.get_crit_bonus()            ← 持有者的临时加成
→ rng.randf() < clamp(总暴击率, 0, 0.95)
```

暴击倍率由 `GameState.get_crit_mult()`（基础 2.0 + 技能树）在 `build_damage()` 里乘上。

> **为什么必须一次射击只掷一次骰**：樱花霰弹枪一发 5 瓣，
> 如果每瓣独立掷骰，暴击会变成「随机 1~5 瓣暴击」，数值方差巨大且不可预期。
> 整发共享暴击结果 → 要么全暴要么全不暴，玩家能明确感知「这一发是暴击」。

## 5. 武器生命周期

```
WeaponData(.tres)
   │  WeaponRegistry.create_node()   ← 唯一创建入口
   │      ① data.script_path 非空 → 用专属脚本（如 WeaponCherryShotgun）
   │      ② 否则按 kind：MELEE → WeaponMelee，其余 → WeaponRanged
   ▼
WeaponBase 实例
   │  setup(data, holder)
   │  _build_visual()  ← 用 data.get_icon() 造 Sprite2D
   ▼
每帧  Player._update_weapons()
        w.global_position = player.global_position + (0, -9)
        w.update_aim(aim_direction)        ← 算 muzzle_point
        w.z_index = 1 if 朝下 else -1      ← 朝上时画在角色身后
   ▼
开火  try_fire()
        can_fire()           查冷却 / 弹药 / 能量
        consume_mp()         扣能量
        _do_fire()           ★ 子类唯一实现入口
        consume_shot()       扣弹 + 进冷却 + 后坐()
        emit fired / EventBus.weapon_fired
   ▼
换弹  start_reload() → _reload_timer → _finish_reload()
```

### 子类只允许覆写这三处
| 方法 | 用途 |
|---|---|
| `_do_fire()` | **必须**实现：一次开火的全部表现 |
| `_do_reload_start()` | 可选：换弹表现 |
| `_on_setup_done()` | 可选：初始化自己的额外节点 |

冷却、弹药、能量、后坐、换弹进度**全部由基类处理**，子类不要重复实现。

### 武器槽与持久化
- `Player.weapons[2]` 两个槽，`1` / `2` 键切换。
- 装备后写回 `GameState.equipped_weapons[slot]`，
  所以**换场景 / 回大厅武器不丢**（存档也会保存）。
- 初始武器只在 `GameState.reset_new_game()` 发放一次。

### 近战攻击盒几何
`WeaponMelee._shape_melee_hitbox()` 用**矩形近似扇形**：

```
reach  = melee_range
height = 2 × reach × sin(arc/2)
位置   = (reach/2, 0)，旋转 = 瞄准角
```

## 6. 击退、顿帧、屏幕震动

| 效果 | 触发 | 实现 |
|---|---|---|
| 击退 | `DamageInfo.knockback` | `Actor.apply_knockback()` → 累加到 `knockback_velocity`，每帧按 `knockback_decay` 衰减，叠加到 `velocity` |
| 顿帧 | `DamageInfo.hitstop` | `VitalsComponent` emit `EventBus.hitstop_requested` → `RunManager` 把 `Engine.time_scale` 压到 `0.06`，持续 `duration` **真实秒** 后恢复 `1.0` |
| 屏幕震动 | `DamageInfo.screen_shake` / 武器 `shake_on_fire` | emit `EventBus.screen_shake_requested`（第一阶段只广播，相机震动控制器留待第二阶段） |

**顿帧的两个坑（已踩过）**
1. `RunManager._process` 里的 `delta` 已被 `time_scale` 缩放，
   必须 `real_delta = delta / Engine.time_scale` 才能按真实时间计时。
2. 连续命中时**不要叠加**顿帧（`_hitstop_left > 0` 直接 return），
   否则密集命中会把时间冻死。想手动清除用 `RunManager.reset_time_scale()`。

## 7. 玩家控制与技能

### 输入的唯一入口是 `Player`
其它系统（武器、技能）通过 `Player.get_move_input()` / `Player.aim_direction()` 取意图，
**不要各自读 `Input`**。

### 状态
| 变量 | 含义 |
|---|---|
| `desired_velocity` | 本帧期望速度（基类读它做加减速） |
| `is_rolling` | 翻滚中（期间由技能接管位移，`_handle_movement` 直接 return） |
| `is_dead` | 死亡 |
| `_guaranteed_crit_left` | 翻滚后的必暴窗口剩余时间 |

### 主动技能（CharacterSkill）
```
CharacterSkill（基类，scripts/entities/skills/character_skill.gd）
   can_use() → 检查死亡 / 冷却 / 能量 / 施放中
   try_use() → 扣能量 → cooldown_left = effective_cooldown() → _perform()
   _perform() ★ 子类必须实现
```
- 冷却、耗能、可用性判断全在基类；子类只管效果与表现。
- **技能不得直接改血量**，只能用 Actor 的公开接口
  （`apply_knockback` / `set_z_height` / `vitals.heal` …）。
- 技能读取「全局强化」的**唯一途径**是 `SkillTreeService.has_tag()`。

### 游侠 · 翻滚（`RogueRoll`）★
| 项 | 值 |
|---|---|
| 时长 | `0.30s × scale`，scale = clamp(翻滚距离 / 68, 0.7, 1.5) |
| 距离 | `StatKind.ROLL_DISTANCE`，基础 68px |
| 无敌 | 全程 `vitals.invincible = true` |
| 必暴窗口 | 结束后 0.65s 内下一次攻击必定暴击 |
| 冷却 | `StatKind.ROLL_COOLDOWN`（角色基础 1.20s，技能树可减） |
| 2.5D 表现 | 抛物线抬升 `sin(p·π) × 7px` + 4 个残影 |
| 技能树联动 | 标签 `double_roll` → 充能 +1 |

> **实现要点**：翻滚推进写在 `_physics_process` 里，**不用**
> `while ... await get_tree().physics_frame` 的协程循环。
> 原因：headless/高帧率下 process delta 与 physics delta 不一致，
> 用 process delta 累加但等 physics_frame 会让时长严重失真（实测翻滚几乎不结束）。

### 手刀（徒手攻击）
没装备武器时按左键触发 `Player._unarmed_attack()`：
用 `MeleeHitbox` 打一次 `StatKind.MELEE_DAMAGE × 全局伤害倍率`，同样吃必暴。

## 8. 敌人 AI（数据驱动）

```
Enemy._physics_process
   ├─ 计时器推进（_state_timer / _attack_cd / 跳跃冲量）
   ├─ _update_target()      索敌（detect_radius 进入 / lose_radius 脱离）
   ├─ _tick_behavior(delta) ★ 按 data.behavior 分发
   └─ super._physics_process(delta)   ← Actor 统一做移动/击退/闪白
```

### 状态机（共用枚举 `Enemy.State`）
```
IDLE → CHASE → WINDUP → ATTACK/RECOVER → CHASE
                 └─ CHARGE（冲锋型）
                 └─ DEAD
```

### 行为类型与关键参数
| `behavior` | 关键参数 | 说明 |
|---|---|---|
| `chase_melee` | `attack_range / attack_windup / attack_recover` | 通用追击 |
| `hopper` | — | 蓄力压扁 → 起跳（`z_height` 抛物线）→ 落地停顿；落地时结算一次攻击 |
| `erratic_flyer` | `hover_height` | 正弦飘移 + 常驻浮空高度 |
| `ranged_kiter` | `attack_range / projectile_*` | 维持理想距离 + 侧向游走 |
| `charger` | `charge_windup / charge_speed_mult` | 蓄力发抖 → 直线冲锋 |
| `boss_summoner` | `burst_count / burst_interval` | 扇形齐射 / 12 发环形 / 召唤 2 只小怪 |

**受击打断**：非 BOSS 在 `WINDUP` 状态被打中会退回 `CHASE`（BOSS 不打断，保持压迫感）。

### 新增 behavior 的三步
1. `Enemy._tick_behavior()` 加一个 `match` 分支 + 实现 `_behavior_xxx()`
2. `tools/validation.gd::_check_data_integrity()` 的 `valid_behaviors` 数组加上新值
3. 同步更新本文档与 03 号文档的表格

## 9. 表现统一入口：CombatFx

`scripts/core/combat_fx.gd` —— **禁止**业务代码自己 `new Label` / `new Sprite2D` 做临时特效。

| 方法 | 用途 |
|---|---|
| `damage_number(ctx, pos, amount, crit, color)` | 伤害飘字（暴击加大加黄 + "!"） |
| `popup(ctx, pos, text, color)` | 通用飘字（拾取、提示） |
| `hit_spark(ctx, pos, dir, scale)` | 命中火花 |
| `muzzle_flash(ctx, pos, dir, scale)` | 枪口火焰 |
| `death_burst(ctx, pos, color, count)` | 死亡爆散 |
| `spawn_sprite_burst(ctx, pos, tex, count, color, speed)` | 通用粒子爆散（樱花花瓣用这个） |

- 特效节点挂在 `group "fx_root"` 下（关卡自建 `FxRoot`）。
  挂在实体上会因为实体 `queue_free` 而一起消失。
- 数量上限：飘字 48、火花 96（`MAX_FLOATING` / `MAX_SPARKS`），防止刷屏掉帧。

### 受击闪白
用 `assets/vfx/sprite_flash.gdshader`，通过 `Actor.flash_white(duration, color)` 触发。
**不要用 `modulate` 模拟闪白**（会整体变暗而不是变白）。

## 10. 数值调优速查

| 想调什么 | 改哪里 |
|---|---|
| 角色属性（生命/护甲/移速/暴击） | `data/characters/ranger.tres` |
| 武器伤害/射速/弹匣/散布 | `data/weapons/<id>.tres` |
| 樱花霰弹枪的花瓣数与散布 | `WeaponData.projectile_count` / `spread_deg`；常量在 `WeaponCherryShotgun` |
| 敌人血量/速度/攻击节奏 | `data/enemies/<id>.tres` |
| 掉率 | `data/loot_tables/*.tres` 的 `weapon_*` 字段 |
| 技能树效果 | `data/skills/global_tree.tres` 的节点 `effects` |
| 玩家的受击无敌时长 | `VitalsComponent.PLAYER_IFRAME` |
| 顿帧强度 | `RunManager.HITSTOP_SCALE` |
| 全局手感（加减速、击退衰减） | `Actor.acceleration / friction / knockback_decay`（场景里 `@export` 可覆盖） |

改完 `.tres` 后**跑一遍 `SmokeTest.tscn`**，它会打印实际生效的关键数值。
