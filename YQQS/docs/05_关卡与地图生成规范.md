# 05 · 关卡与地图生成规范

> 森林关卡（宁静森林）是**程序化生成**的。
> 本文说明生成算法、渲染分层、内容摆放规则，以及「加一张新地图」的标准做法。
>
> ✅ **地图渲染已改为双网格（dual-grid）系统瓦片**（2026 新版）。
> 下文 §4.2 / §4.3 描述的是**旧**的 16px 瓦片平铺方式，保留作为对照；
> 当前实现见 [`10_美术素材规格与双网格瓦片契约.md`](10_美术素材规格与双网格瓦片契约.md) §5
> 与 `scripts/core/dual_grid.gd`。**生成算法（§3）、内容摆放（§5）完全没变** ——
> 双网格只换了"怎么画"，没换"画在哪"。

## 1. 职责划分（三层，不得越界）

```
ForestMapConfig (.tres)      纯参数：房间数量/尺寸/密度/摆放规则
        │
        ▼
ForestMapGenerator          纯拓扑：只产出 RoomGraph（不碰任何场景节点）
        │
        ▼
ForestLevel (Node2D)        翻译层：RoomGraph → TileMapLayer + 场景节点 + 刷怪
        │
        ▼
RoomData / RoomGraph       数据容器：房间坐标、门、走廊、刷怪点
```

| 文件 | 职责 | **不做**的事 |
|---|---|---|
| `scripts/data/forest_map_config.gd` | 参数 | 不含算法 |
| `scripts/levels/forest_map_generator.gd` | 拓扑生成 | 不引用任何场景、不发信号、不读存档 |
| `scripts/levels/forest_level.gd` | 渲染 + 摆放 + 流程 | 不含随机布局算法 |
| `scripts/levels/room_graph.gd` / `room_data.gd` | 数据结构与查询 | 无副作用 |

## 2. 坐标系

| 概念 | 单位 | 说明 |
|---|---|---|
| **cell** | 房间格 | 房间在「房间网格」上的坐标，可以是负数 |
| **tile** | 图块 | 16px。`像素坐标 = tile × 16` |
| **world** | 像素 | 实际 `global_position` |

房间内部图块矩形的换算：

```gdscript
interior.position = Vector2i(cell.x * cfg.cell_pitch.x, cell.y * cfg.cell_pitch.y)
interior.size     = cfg.room_interior          # 默认 (22, 16)
```

默认 `cell_pitch = (30, 24)`，房间 `(22, 16)`：
→ 水平间隙 8 格、垂直间隙 8 格，正好容纳 3 格宽的走廊。

## 3. 生成算法（`ForestMapGenerator.generate`）

### ① 随机生长拓扑
```
rooms = {(0,0)}
while rooms.size() < target and attempts < max_attempts:
    随机挑一个已有房间 base
    随机挑一个方向 dir
    cand = base + dir
    若 cand 已有房间 → 跳过
    若 cand 周围已有 ≥2 个房间 → 跳过（避免房间挤成一坨）
    若 cand 周围已有 1 个房间：
        以 loop_chance 概率打通（形成环路），否则跳过
    否则 → 加入 cand
```
**关键性质：生成即连通**，不需要事后修复。
`loop_chance = 0.18` 意味着绝大多数是树状结构 + 少量环路。

**兜底**：如果约束太严导致房间数不足下限，会放宽限制再长一轮，
保证一定拿到 ≥ `room_count_min / 2` 个房间。

### ② 计算几何
按 `cell_pitch` 算出每个房间的 `interior`，然后 `graph.recompute_bounds()`。

> ⚠️ **踩过的坑**：`RoomGraph.add_room()` 时房间还没有 `interior`，
> 所以 `_grow_bounds()` 在几何阶段之前是空操作。
> 必须在几何算完后调用一次 `recompute_bounds()`，
> 否则 `bounds` 是空矩形 → 相机 limit 全为 0 → 镜头被锁死在地图原点。

### ③ BFS 距离
从 `start_cell` 做 BFS，填每个房间的 `depth` 与 `neighbors`。
`build_distances()` 会返回**不可达房间列表**（正常情况下必须为空，
`Validation.tscn` 会断言这一点）。

### ④ 分配房间类型

| 条件 | 类型 |
|---|---|
| depth == 0 | `ENTRANCE` 出生房 |
| 在最远 25% 且是死路里随机挑一个 | `BOSS` 房 |
| 剩余死路（按 depth 从远到近） | `TREASURE` 宝箱房 ×2 |
| depth 较深的普通房 | `ELITE` 精英房 ×2 |
| 其余 | `COMBAT` 普通战斗房 |

同时给每个房间算 `enemy_budget`（刷怪预算）：

| 房间类型 | 预算 |
|---|---|
| ENTRANCE | 0 |
| TREASURE | 0–2 |
| COMBAT | 3–6 |
| ELITE | 2–4 |
| BOSS | 1（BOSS 本体） |

### ⑤ 门与走廊
房间在网格上只与**轴相邻**的格子相连，所以走廊**永远是直线**，不需要 L 形拐弯算法。

```
东向（dir == E）：
    y  = a.interior 中心行
    x0 = a.interior 右边界        x1 = b.interior 左边界 − 1
    走廊矩形 = Rect2i(x0, y−half, x1−x0+1, corridor_width)
    门 a = (a 内部最右列, y)       门 b = (b 内部最左列, y)

北向（dir == N，a 在南 b 在北）：
    走廊矩形 = Rect2i(x−half, b 下边界, corridor_width, a 上边界−b 下边界+1)
```

**只处理 N / E 两个方向**（`_is_forward()`），保证每对相邻房只生成一次走廊。

`doors` 字典记录的是**房间内部贴着走廊那一格**（不是墙上的洞），
刷怪与装饰都会避开门口 ±2 格，防止堵门。

## 4. 渲染（`ForestLevel`）

### 4.1 节点骨架（`_build_nodes`）

```
ForestLevel (Node2D)
├── Background (Polygon2D)       z=-100，地图外的黑底
├── Ground (TileMapLayer)        z=-50，地板 + 墙体（不做 y-sort）
├── EntityRoot (Node2D)          ★ y_sort_enabled = true   [group: entity_root]
│   ├── Props (Node2D)             树木/岩石/灌木（y_sort）
│   ├── Pickups (Node2D)           掉落物                [group: pickup_root]
│   └── Projectiles (Node2D)       投射物                [group: projectile_root]
│   └── (玩家 / 敌人 / 宝箱 / 传送门 直接挂这里)
├── FxRoot (Node2D)              z=20                    [group: fx_root]
└── HudLayer (CanvasLayer, 10)
    └── Hud.tscn
```

**地面不做 y-sort**：地板永远在最底层。需要遮挡关系的（树、角色、掉落物）
全部放进 `EntityRoot` 这个 y-sort 容器，靠 `position.y` 排序。

### 4.2 地板铺设（`_paint_ground`）
```
① 每个房间内部 → 按 floor_tiles 权重随机铺
   特殊房间覆写：ENTRANCE→STONE_1，TREASURE→LEAVES_GROUND，BOSS→ALTAR_FLOOR
② 每条走廊 → 按 corridor_tiles 权重随机铺（泥土路）
③ 墙体：所有地板的 8 邻域里「不是地板」的格子 → wall_tile（MOSS_CLIFF）
④ 写入 TileMapLayer
⑤ 背景多边形按 tile_bounds_with_margin(6) 铺满
```
实测（seed 20240601，9 房间）：**地板 3360 格 / 墙体 768 格**。

### 4.3 TileSet 构建（`ForestTileset`）
代码构建，不手写 `.tscn` 里巨大的内嵌 TileSet：

```gdscript
ts.tile_size = Vector2i(16, 16)
src.texture = Atlas.tile_atlas()
src.texture_region_size = Vector2i(16, 16)
for y in 8: for x in 8: src.create_tile(Vector2i(x, y))
ts.add_physics_layer(0)
ts.set_physics_layer_collision_layer(0, Layers.WORLD)
for t in SOLID_TILES:                      # 22 个图块
    td.add_collision_polygon(0)
    td.set_collision_polygon_points(0, 0, 16×16 方块)
```

新增可碰撞图块 → 加进 `ForestTileset.SOLID_TILES`。

### 4.4 装饰（`_decorate`）
密度按房间面积算，并对特殊房间打折：

| 房间 | 密度系数 |
|---|---|
| ENTRANCE | 0.4（留活动空间） |
| BOSS | 0.5 |
| TREASURE | 0.7 |
| 其它 | 1.0 |

| 装饰 | 密度 | 碰撞 |
|---|---|---|
| 树（PINE / DEAD_TREE） | `tree_density` 0.055 | ✅ 半径 5 的 `StaticBody2D`（OBSTACLE 层） |
| 岩石 / 树桩 | `rock_density` 0.030 | ✅ |
| 灌木 / 花 / 蘑菇 / 高草 | `bush_density` 0.10 | ❌ |
| 走廊碎石 | `corridor_decor_density` 0.03 | ❌ |

**摆放规则**（`_scatter_in_rect`）：
- 离房间墙 ≥ `decor_wall_margin`
- `_blocked` 表去重（一格不放两个）
- **有碰撞的装饰不得出现在门口 ±2 格内**（`_too_close_to_any`）
- 找不到位置就放弃（有 `max_attempts` 上限，不会死循环）

实测：**树 137 / 岩石 73 / 灌木花草 254**。

## 5. 内容摆放

### 5.1 刷怪点预计算（`_collect_spawn_points`）
每个房间先生成 `enemy_budget + 6` 个候选点，条件：
- 在地板内、不在 `_blocked` / `_walls` 上
- 离墙 ≥ `enemy_wall_margin`（3 格）
- 离门 ≥ 2 格
- 彼此间距 ≥ `enemy_min_spacing`（3 格）

`chest_spawn_points` 复用同一份点（宝箱不会和怪重叠的位置）。

### 5.2 刷怪（`_spawn_room_enemies`）
```
池 = ELITE 房 → ConfigDB.forest_elite_enemies()（空则退回普通）
                        否则 → ConfigDB.forest_normal_enemies()
每只怪：按 spawn_weight 加权随机挑一个 EnemyData
        _instantiate_enemy(data, pos, room.cell)
```
`_instantiate_enemy` **必须先 `configure()` 再 `add_child()`**，
因为 `Enemy._ready()` 就需要 `data`。

### 5.3 BOSS（`_spawn_boss`）
`ConfigDB.forest_boss()` → 放在 BOSS 房正中，房间刷怪预算为 1。
BOSS 生成时 `Enemy._ready` 会 emit `EventBus.boss_spawned` → HUD 显示 BOSS 血条。

### 5.4 宝箱（`_spawn_room_chests`）

| 房间 | 数量 | 等级 |
|---|---|---|
| TREASURE | `chests_per_treasure_room`（1–2） | `treasure_chest_tier` = 优秀 |
| COMBAT / ELITE | `room_chest_chance`（25%）→ 1 个 | 普通 |
| BOSS | 1 个（房中央偏移 26px） | 稀有 |

> 小怪/精英/BOSS **死亡时**的宝箱由 `LootService.handle_enemy_death()` 生成，
> 等级由 `EnemyData.get_chest_tier()` 推导（NORMAL→普通 / ELITE→优秀 / BOSS→稀有）。

### 5.5 传送门（`_place_portals`）

| 传送门 | 位置 | 行为 |
|---|---|---|
| 返回门 | 出生房左下角 | `RunManager.end_run(false)` → 回大厅（放弃本局） |
| 出口 | BOSS 房中央上方 40px，**初始隐藏** | 击败 BOSS 后出现并放大弹入；交互 → `end_run(true)` → 回大厅 |

BOSS 击败由 `ForestLevel._on_boss_defeated()` 处理：
标记房间清空 → 显示出口 → toast「出口已开启」→ 屏幕震动。

## 6. 运行时房间状态

`ForestLevel._room_enemies: Dictionary[Vector2i → Array[Node]]` 记录每个房间的敌人。

```
Enemy 死亡 → EventBus.enemy_died(enemy, tier, pos)
   → ForestLevel._on_enemy_died 从对应房间列表里删掉
   → _check_room_cleared(room)  统计存活数
   → 存活数 == 0 且（非 BOSS 房 或 BOSS 已死）
        → room.cleared = true
        → 发金币（4 + depth×2）
        → EventBus.room_cleared / toast
```

`_process` 里每帧比对玩家所在房间（`graph.get_room_at_world`），
变化时 emit `EventBus.room_entered(room, kind)` → HUD 提示「发现宝箱房 / 精英怪出没 / BOSS 房」。

## 7. 随机与可复现性

**所有地图随机必须来自 `RunManager.map_rng`**（由 `run_seed` 派生）。

```gdscript
RunManager.start_run(seed)      # seed < 0 时用系统时间
   → map_rng.seed = run_seed
   → combat_rng.seed = run_seed ^ 0x5EED
   → LootService.rng.seed = run_seed ^ 0xBEEF
```

`ForestLevel._generate()` 会把自己的 `_rng` 指向 `RunManager.map_rng`，
并用 `level_seed` 覆写种子（`< 0` 时用 `RunManager.run_seed`）。

**验证**：`Validation.tscn` 用同一 seed 生成两次，比对房间数与每个房间的门数量；
再用不同 seed 生成，断言布局不同。

> ⚠️ 生成器里**禁止** `randf()` / `randi()`。用了就无法同种子复现，
> 「同种子同地图」这条保证会静默失效。

## 8. 加一张新地图（第二阶段流程）

1. **参数**：复制 `data/levels/forest_config.tres` 改名（例如 `cave_config.tres`），
   调 `room_interior / cell_pitch / floor_tiles / wall_tile / 密度`。
2. **图块**：如果新地图要用另一套地表，扩展 `Atlas.SHEETS` 加一张图集，
   并给 `ForestTileset` 加一个 `build_from(sheet_name, solid_tiles)` 的兄弟实现
   （或把图集名参数化）。
3. **关卡脚本**：`ForestLevel` 已经比较通用，主要要改的是
   `_room_floor_tile()`（房间类型→地表）、`_decorate()` 的装饰工厂、`_spawn_boss()`。
   建议把「装饰工厂」抽成一个 `LevelDecorator` 资源，而不是复制一份 `ForestLevel`。
4. **登记**：`ConfigDB.DATA_DIRS["levels"]` 已经会自动扫描，无需改代码。
5. **场景 ID**：在 `GameEnums.SCENE_PATHS` 加一条 `"cave": "res://scenes/levels/cave/CaveLevel.tscn"`。
6. **传送门**：大厅加一个 `Portal`（新 `Portal.Kind`），`Lobby._enter_cave()` 里
   `RunManager.start_run(seed, floor)` + `SceneRouter.go_to("cave")`。

> **建议的重构时机**：当出现第二张地图时，把 `ForestLevel` 里的
> 「地表选择 / 装饰工厂 / BOSS 选择」抽成资源（`LevelTheme`），
> 让 `ForestLevel` 变成通用的 `DungeonLevel`。
> 第一阶段故意没有提前抽象 —— 一张地图时抽象只会增加阅读成本。

## 9. 调试

- `ForestLevel.debug_report()` 返回房间类型统计与存活敌人数。
- `RoomGraph.dump_log()` 返回生成过程日志（目标房间数、实际房间数、每条走廊）。
- `Validation.tscn` 会打印 5 个种子的房间类型分布，例如：
  ```
  seed 1003：11 个房间 { ENTRANCE:1, COMBAT:5, ELITE:2, TREASURE:2, BOSS:1 }
  ```
- 想固定看某个种子：`ForestLevel.level_seed = 20240601`（场景里是 `@export`）。
