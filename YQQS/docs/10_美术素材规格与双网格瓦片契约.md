# 10 · 美术素材规格与双网格瓦片契约

> 本文是**代码与美术之间的第二份契约**（第一份是 `scripts/core/atlas.gd`）。
> 用途：把「我要什么尺寸、什么网格、第几格放什么」写成机器可读的表格，
> 交给外部图像生成工具（GPT Image 2）按文件名产出，再由本工程无缝替换。

> 目标风格从《元气骑士》切到 **《元气骑士前传》**；地图渲染从
> **16px 瓦片平铺** 切到 **双网格（dual-grid）系统瓦片**。
>
> 📌 **本文只定义契约，不改任何代码。** 等新素材库落地后再执行替换，见 §9。

### 0.2 关键事实（决定了新素材的硬约束）

| 事实 | 出处 | 对素材的影响 |
|---|---|---|
| 逻辑分辨率 **480×270**，窗口 1440×810（3×） | `project.godot` | 一屏 30×17 格（16px 图块） |
| `stretch/mode = canvas_items` + `scale_mode = integer` | `project.godot` | 所有精灵必须**像素完美**，不能有半像素设计 |
| `default_texture_filter = 0`（最近邻） | `project.godot` | 生成图**不得**含抗锯齿/柔边，否则放大后出灰边 |
| 图块尺寸常量 `Atlas.TILE_SIZE = 16` | `scripts/core/atlas.gd` | 地面瓦片必须严格 16×16 |
| 房间内部 22×16 格、走廊 3 格宽 | `scripts/data/forest_map_config.gd` | 双网格需要 ≥2 格宽的连续区域才看得出效果 |
| 敌人每动画最多 3 帧（`ENEMY_ANIMS`） | `scripts/core/atlas.gd` §ENEMY_ANIMS | 新敌人图集最小可 1 列，**建议 4 列**（见 §4.2） |
| 图集路径**全部**走 `Atlas.SHEETS` 常量表 | `scripts/core/atlas.gd` | 文件名/网格一旦定死，替换时**只能换图片不能改文件名** |

### 0.3 现有地图渲染的问题（为什么要上双网格）

`ForestLevel._paint_ground()` 现在的做法：

```
① 房间内部：从 floor_tiles（GRASS_1..4）按权重逐格随机铺
② 墙体：所有地板的 8 邻域里「不是地板」的格子 → 统一填 wall_tile（CLIFF_SIDE）
```

由此产生三个可见缺陷：

1. **棋盘感**：GRASS_1..4 只是 4 张噪点不同的 16×16 图，随机平铺后是均匀麻点，
   看不到「草地成片、泥土成路、石头成滩」的地貌结构 —— 这正是《元气骑士》地牢的做法。
2. **收边靠猜**：草/泥边界只有 `GRASS_EDGE_A/B` 两张**竖直方向**的图，
   斜角、内凹角、拐弯全部用不上正确图块，边界是「锯齿+断裂」。
3. **墙是贴纸**：`CLIFF_SIDE` 单张图块铺满所有非地板格，不区分朝向，
   悬崖没有上沿/下沿/外角/内角，看起来像贴了一圈墙纸。

**《元气骑士前传》的做法**是反过来：地表是**成片的地貌**（草地/土路/石地大块过渡），
边界由角点驱动自动衔接。用**双网格系统**可以用 **16 张瓦片/地表** 覆盖全部
16 种角点组合，不需要 47 张 blob，也不需要手绘过渡条 —— 这就是本文 §5 的契约。

## 1. 风格定义（写进每条提示词的前缀）

新的画风基准 = **《元气骑士前传》**，与本工程已有技术约束对齐后的可执行描述：

| 维度 | 规定 |
|---|---|
| 视角 | 2.5D **俯视微倾**（顶部略可见、正面为主），不是正俯视也不是侧视 |
| 像素密度 | 图块 16×16；角色 32×32；BOSS 64×64。**角色约占格子 26–30px 高** |
| 描边 | **统一近黑描边 1px**（`#0d0b1f` 或同色系最深色），BOSS 可用 2px |
| 明暗 | **2 阶明暗 + 1 个高光点**：基色、暗部（-25% 亮度）、高光（顶部 1–2px 亮边） |
| 光源 | 固定左上 45°；右下必须有暗部；地面物件的投影朝右下 |
| 饱和度 | 中高饱和、明亮；暗部**不许发灰**，要保留色相（偏冷紫或偏暖棕） |
| 轮廓可读 | 剪影优先：任意素材缩到 16×16 仍能认出是什么 |
| 细节 | **禁止**抖动（dither）噪点滩、禁止超过 3 阶渐变、禁止细碎纹理 |
| 色调分族 | 森林=草绿/棕；遗迹=冷灰蓝；魔阵=紫粉；危险=暗红橙 |

## 2. 交付硬约束（不合格直接退回）

| # | 约束 | 判定方式 |
|---|---|---|
| 1 | **文件名逐字一致** | 与 §3 表格的 `文件名` 列**完全一致**（含下划线、复数、大小写） |
| 2 | **画布尺寸逐像素一致** | 宽高必须等于 `尺寸` 列；不接受「差不多」或「等比接近」 |
| 3 | **透明背景** | 只允许纯 `#00000000` 全透明；**禁止**白底、棋盘格底、阴影底、渐变底 |
| 4 | **严格网格对齐** | 每格内容必须**居中且不跨格**；格与格之间不得有 1px 粘连 |
| 5 | **无抗锯齿** | 每个像素必是不透明或全透明；不得出现半透明柔边像素 |
| 6 | **只用 §1.1 调色板** | 后续用脚本吸附；提交时尽量已收敛 |
| 7 | **不留文字/水印/编号** | 格子上不许写 "1,2,3"、不许有投影标题、不许有画布边框 |
| 8 | **不留拼版辅助线** | 不许画格子分隔线、不许画洋红/青色定位框 |
| 9 | **方向约定固定** | 角色/敌人：**第 1 列=面向下（朝镜头）**，方向顺序见各表 |
| 10 | **不改文件名语义** | 不许把 `enemy_*.png` 改成 `mob_*.png`；`Atlas.SHEETS` 是硬编码的 |

### 2.1 生成工具的现实限制（重要）

GPT Image 2 **不能保证**输出精确到 16px 的像素画，也不能保证 4×4 网格分毫不差。所以流程必须是：

```
① 用 §11 的提示词生成（要求「整数倍放大、无模糊」）
② 用工具做归一化：缩小/放大到目标尺寸（最近邻） → 吸附到 §1.1 调色板
③ 人工切片到网格（Aseprite / ImageMagick）
④ 跑 §8 的校验脚本，不通过就回到 ①
```

> 我在 §8 给了一个**零依赖校验器**方案（Godot headless）：
> 尺寸、网格是否越界、是否含半透明像素、颜色是否越出调色板、格子是否为空。

## 4. 逐文件格子语义表

> 左列为**格坐标 (col,row)**，原点在左上角，从 0 开始。
> 「向下」= 朝镜头（+y），「向上」= 背对镜头（−y），「侧向」= 朝右（代码里镜像翻左）。

### 4.1 `player_ranger.png`（32px，4×4）

| | col 0 | col 1 | col 2 | col 3 |
|---|---|---|---|---|
| **row 0** | 向下·待机 | 向下·走 A | 向下·走 B | **向下·翻滚** |
| **row 1** | 向上·待机 | 向上·走 A | 向上·走 B | **向上·翻滚** |
| **row 2** | 侧向·待机 | 侧向·走 A | 侧向·走 B | **侧向·翻滚** |
| **row 3** | 受击 | 攻击（拉弓） | 死亡 | 冲刺 |

对应常量：`Atlas.P_IDLE_DOWN … P_DASH`。**顺序不可变。**

## 5. 双网格（Dual-Grid）瓦片契约 ★核心

### 5.1 为什么要它

传统做法：**逻辑格 = 显示格**，一个 16px 格子画一张图。
要平滑衔接就必须对「上/右/下/左 4 邻居 + 4 对角 = 8 邻居」的全部组合出图 → **47 张（blob）**。
缺一张就出现「边界断线」。

双网格做法：**逻辑格与显示格错开半格**。

```
逻辑格（A 格）: 决定「这里是不是草地」—— 数据、碰撞、刷怪都在这里
显示格（B 格）: 画图的位置，偏移 (-8,-8)，即 &minus;半个瓦片
```

一个显示格恰好压在 **4 个逻辑格的公共角点** 上，所以：

> **显示格只需要知道自己压着哪 4 个逻辑格 → 16 种组合 → 16 张瓦片，无缝覆盖全部角点情况。**

不再出现「直边/斜角/内凹/外凸」缺图，因为**角点组合已经被穷举完了**。

### 5.2 坐标与偏移（必须逐字实现）

```gdscript
const TILE := 16          # Atlas.TILE_SIZE
const HALF := TILE / 2    # 8 —— 显示格相对逻辑格的偏移量

# 逻辑格 (col,row) 的左上角像素坐标
#   cell_origin = Vector2(col, row) * TILE
#
# 显示格 (col,row) 的锚点（即该显示格的左上角像素坐标）
#   它由逻辑格 (col-1, row-1) 的右下角 = cell_origin(col-1,row-1) + (TILE,TILE)
#   = Vector2(col-1, row-1) * TILE + Vector2(TILE, TILE)
#   = Vector2(col, row) * TILE
#
# ⇒ 实现上：显示格 TileMapLayer 只需整体偏移 Vector2(-HALF, -HALF)
#           然后按「显示格坐标 = 逻辑格坐标」写同一套格坐标即可。
```

**判定式**（`cell(x,y)` = 逻辑格 (x,y) 是否为该地表）：

```
显示格 (col,row) 压着 4 个逻辑格：
    ┌───────────────┬───────────────┐
    │  (col-1,row-1) │  (col,row-1)   │   ← 上排：左=NW 右=NE
    ├───────────────┼───────────────┤
    │  (col-1, row)  │  (col, row)    │   ← 下排：左=SW 右=SE
    └───────────────┴───────────────┘

角点 → 地形索引位（直接当 4-bit 下标，值 1 = 该角是本地形）：
    NW = bit 3 (值 8)
    NE = bit 2 (值 4)
    SW = bit 1 (值 2)
    SE = bit 0 (值 1)

tile_index = NW*8 + NE*4 + SW*2 + SE*1     ∈ [0,15]
```

**直接给出 16 个索引的完整表**（row = 高 2 位，col = 低 2 位）：

| tile_index | col,row | NW | NE | SW | SE | 画出来是什么 |
|---|---|---|---|---|---|---|
| 0  | 0,0 | 0 | 0 | 0 | 0 | 空 |
| 1  | 1,0 | 0 | 0 | 0 | 1 | 左上角（1/4 圆角） |
| 2  | 2,0 | 0 | 0 | 1 | 0 | 右上角（1/4 圆角） |
| 3  | 3,0 | 0 | 0 | 1 | 1 | 上边（下半满） |
| 4  | 0,1 | 0 | 1 | 0 | 0 | 左下角（1/4 圆角） |
| 5  | 1,1 | 0 | 1 | 0 | 1 | 左上+右下对角（两个 1/4 圆） |
| 6  | 2,1 | 0 | 1 | 1 | 0 | 右上+左下对角（两个 1/4 圆） |
| 7  | 3,1 | 0 | 1 | 1 | 1 | 除左下外全满（**外凹角**） |
| 8  | 0,2 | 1 | 0 | 0 | 0 | 右下角（1/4 圆角） |
| 9  | 1,2 | 1 | 0 | 0 | 1 | 左下+右上对角 |
| 10 | 2,2 | 1 | 0 | 1 | 0 | 左边（右半空） |
| 11 | 3,2 | 1 | 0 | 1 | 1 | 除右上外全满（外凹角） |
| 12 | 0,3 | 1 | 1 | 0 | 0 | 下边（上半满） |
| 13 | 1,3 | 1 | 1 | 0 | 1 | 除右下外全满（外凹角） |
| 14 | 2,3 | 1 | 1 | 1 | 0 | 除左上外全满（外凹角） |
| 15 | 3,3 | 1 | 1 | 1 | 1 | 全满（纯地表填充） |

> **注意 idx 0 也必须有图**（即便它代表「四角都不是本地形」）——
> 因为显示网格覆盖的范围比逻辑网格大一圈，边缘会出现 idx 0。
> 规则：`idx 0` 画**背景/下层地形**（例如草地之下的深色土壤或纯黑），不要留透明。
> 留透明会导致相机边缘出现空洞。

### 5.3 图集布局：`tileset_forest_ground.png`（256×256，16 列 × 16 行）

每张地表占 **4 列 × 4 行 = 16 格**，块行列 = `tile_index` 的 (col, row)。
4 种地表按 2×2 拼成大图：

| 地表 | 块位置 | 索引范围 | 用途 |
|---|---|---|---|
| **草地 GRASS** | 块 (0,0)，即整图 col 0–3 / row 0–3 | 0–15 | 房间默认地表（`floor_tiles` → 单值，不再随机 4 变体） |
| **泥土 DIRT** | 块 (1,0)，col 4–7 / row 0–3 | 16–31 | 走廊地表（`corridor_tiles`） |
| **石板 STONE** | 块 (0,1)，col 0–3 / row 4–7 | 32–47 | 入口房 / 遗迹房 |
| **圣坛 SANCTUM** | 块 (1,1)，col 4–7 / row 4–7 | 48–63 | BOSS 房（紫粉魔阵调） |
| 空 | 块 (2,0)/(3,0)/(2,1)/(3,1) col 8–15 | 64–255 | **留空（纯透明）**，给后续地图用（洞穴/雪原/沙漠…） |

**每块内部索引公式**：

```gdscript
# 第 f 种地表的第 i 个角点瓦片（i ∈ 0..15）
const BLOCK_ORIGIN := [Vector2i(0,0), Vector2i(4,0), Vector2i(0,4), Vector2i(4,4)]  # 草/泥/石/坛
static func ground_coords(terrain: int, i: int) -> Vector2i:
    return BLOCK_ORIGIN[terrain] + Vector2i(i % 4, i / 4)
```

### 5.4 每张瓦片必须遵守的几何（**这是提示词里最容易被忽略、也最致命的一条**）

以「草地」为前景、背景为深色土壤为例，块内 4×4 的 16 张图（**严格按 §5.2 的表**）：

| 类别 | 索引 | 几何 |
|---|---|---|
| 满格 | 15 | 一张**可无缝平铺**的草地图（16×16，四边可接自己），四角全满 |
| 直边 | 3 / 12 | **下满上缺** / **上满下缺**；交界落在**正中间水平线 y=8**，缺的一侧是背景色 |
| 1/4 圆角 | 1 / 2 / 4 / 8 | 只有**一个角**是本地形，形状是**以格心 (8,8) 为圆心的 1/4 圆** |
| 对角 | 5 / 9 / 6 | **两个对角**各一个 1/4 圆，中间留一条 **4px 宽的对角背景通道** |
| 缺一角 | 7 / 11 / 13 / 14 | 四角中**只有一个缺**，缺口要画成**内凹角** —— 缺口内是背景色，且要有**内侧落影** |
| 全空 | 0 | 整格背景色（**不要透明**），边缘可加极淡纹理 |

其中「缺一角」的四个索引分别是：

```
7  = 缺 SW（左下）     11 = 缺 NE（右上）     13 = 缺 SE（右下）     14 = 缺 NW（左上）
```

**其余通用规则**

- 4 个角弧的**半径必须完全一致**（约 5–6px），否则拼图时圆角会忽大忽小。
- 地表与背景交界处必须有 **1–2px 更深的根线 + 背景侧的接触落影** ——
  这正是「平滑衔接」的观感来源，没有它看起来还是硬邦邦的锯齿。
- **`idx 15` 必须能无缝自接**：左列像素 == 右列像素、上排 == 下排（逐像素）。

> 视觉验收口决：**把 16 张按 4×4 排开看，应该像一块「被啃过」的方形饼干 ——
> 越靠右下越完整，越靠左上越缺**；四角弧线的半径必须**完全一致**。

### 5.5 相邻地块的过渡（草地→泥土）

**不要**再画「过渡条纹图块」。做法是：

```
① 先用 idx 15 的「泥土」铺满整张地图（最底层，作为世界底色）
② 再用双网格铺「草地」层 → 草地边缘由 16 张瓦片自动画出圆角与落影
③ 两层之间天然形成 3–4px 的深色土壤过渡带（来自草地瓦片自带的草根+落影）
```

于是 `ForestMapConfig` 的 `floor_tiles / floor_tile_weights / floor_edge_tile / wall_tile`
这套「多图块随机」字段全部退役，改为**每种房间类型一个地块 id**：

```gdscript
@export var room_ground_terrain: int = TERRAIN.GRASS      # 默认
@export var entrance_ground_terrain: int = TERRAIN.STONE
@export var treasure_ground_terrain: int = TERRAIN.GRASS
@export var boss_ground_terrain: int = TERRAIN.SANCTUM
@export var corridor_ground_terrain: int = TERRAIN.DIRT
@export var underlay_terrain: int = TERRAIN.DIRT          # 世界底色
```

### 5.6 渲染节点骨架（替换现有 `Ground (TileMapLayer)`）

```
ForestLevel (Node2D)
├── Background (Polygon2D)          z=-100   地图外的黑底（保留）
├── GroundUnderlay (TileMapLayer)   z=-60    整张地图铺 underlay_terrain 的 idx15 ◀ 新增
├── Ground (TileMapLayer)           z=-50    ★ 双网格层，整体 position 偏移 (-8,-8)
│                                            tile_set 用 ground 图集，物理层可选
├── GroundOverlay (TileMapLayer)    z=-45    房间内特殊地块（石板/魔阵）◀ 新增
├── EntityRoot (Node2D, y_sort)     z=0      不变
└── ...
```

**关键实现要点**

1. `Ground.position = Vector2(-8, -8)` —— 半格偏移，**这是双网格的全部魔法**。
2. `Ground` 写入时**遍历逻辑格范围外扩 1 格**（`for y in range(ymin-1, ymax+1)`），
   否则地图最右/最下边缘会缺一行瓦片。
3. 双网格层**不放碰撞**（碰撞仍由逻辑格上的 `wall` 层负责），
   避免「显示格碰撞偏移半格」这个经典 bug。
4. 单元格尺寸仍 16×16：**图块没变，变的是「一个图块表示 4 个逻辑格角点的状态」**。

### 5.7 内容密度调优（视觉收益的第二步）

《元气骑士前传》不像《元气骑士》那样满地碎石，它的地表是**大块连续地貌**。
建议同步调整 `forest_map_config.tres`：

| 参数 | 现在 | 建议 | 原因 |
|---|---|---|---|
| `rock_density` | 0.03 | **0.012** | 石头少了，草地才成片 |
| `bush_density` | 0.10 | **0.05** | 同上 |
| `corridor_decor_density` | 0.03 | **0.015** | 走廊要干净，才看得出泥土路的圆角 |
| `tree_density` | 0.055 | 0.045 | 树仍然要多（森林感） |
| `corridor_width` | 3 | **3**（不变） | 3 格宽刚好能看见双网格两侧圆角 |

### 5.8 正确性验证（零人工看图）

**像素恒等测试**：同一张逻辑地图，用两种方式渲染，**重叠区域必须逐像素相同**。

```
参考图 R（传统 1×1）：遍历每个逻辑格 (x,y)，直接在该逻辑格的 16×16 矩形上
                     画 ground_coords(T, tile_index(x-1,y-1 … x,y)) —— 不偏移。

双网格图 D（新实现）：显示层整体 offset (-8,-8)，按 §5.2 写显示格。
```

**断言**（逐格成立）：

```
D 中「逻辑格 (x,y) 所覆盖的 16×16 区域」
  = 显示格 (x,  y  ) 的 SE 象限  ⊕  显示格 (x+1,y  ) 的 SW 象限
    ⊕ 显示格 (x,  y+1) 的 NE 象限  ⊕  显示格 (x+1,y+1) 的 NW 象限
必须逐像素等于 R 在同一位置的 16×16 像素。
```

实现方式：`tools/validation.gd` 增加一项 `_check_dualgrid()`，
把 R 与 D 各渲染成一个 `Image`，`get_data()` 逐字节比对；
不一致就打印**首个不一致像素坐标 + 该格期望索引 / 实际索引**。

> 这个测试能把 §5.2 的**偏移方向**与**角点→bit 顺序**一次性钉死，
> 不用靠肉眼判断「圆角是不是接反了」—— 而后者在 16px 尺度上几乎无法用眼睛分辨。

## 7. 风险与已知坑

| 风险 | 说明 | 对策 |
|---|---|---|
| **AI 生成图无法像素级精确** | GPT Image 2 输出可能 1024×1024 且带柔边 | 走 §2.1 归一化流程；网格类素材建议「先大后切」 |
| **调色板漂移** | 每批生成颜色都不一样 | 强制吸附 §1.1 32 色；提交前跑校验器 |
| **双网格层放碰撞** | 碰撞会偏移半格，玩家会「卡在看得见的地板外」 | 双网格层 `physics_layers_count = 0`，碰撞只放 `wall` 层 |
| **地图边缘缺行** | 显示网格比逻辑网格大一圈 | 写入时外扩 1 格（§5.6 要点 2） |
| **idx 0 留透明** | 相机边缘出现空洞 | idx 0 必须画背景色（§5.2 注意） |
| **扩网格打断兼容** | `cols/rows` 是编译期常量 | 提交素材时**一次性选定** 3×1 或 4×4 方案 |
| **旧图集被误用** | 代码里还有 `tileset_forest` 的引用 | 替换完成后删除旧文件 + 全局搜索 `tileset_forest` 归零 |

## 8. 素材验收校验器（建议新增 `tools/validate_assets.gd`）

新增素材库落地后，用这个脚本做**机器验收**（零人工看图）：

```
对 assets/sprites/ 下每个 PNG：
  ① 尺寸必须等于 §3 表格的「尺寸」（硬失败）
  ② 每个格子必须「非全空」且「不触边」——内容超出格子边界即失败
     判定：格子最外一圈像素若含不透明像素 → 该格内容越界（软警告，可白名单）
  ③ 不允许半透明像素（alpha ∉ {0,255}）→ 失败
  ④ 统计用色数并比对 §1.1 调色板，报告越色清单（含数量）
  ⑤ 双网格图集额外检查：对每种地形，idx15 的四条边必须能无缝自接
     （左列像素 == 右列像素、上排 == 下排，逐像素比对）
```

第 ⑤ 条是双网格的**可平铺性证明**：只要 idx15 左右/上下自接，重复铺就不会出现接缝。
