# 03 · 数据与配置规范

> 核心原则：**数值不在代码里**。
> 想改一个伤害、一次掉率、一个房间尺寸，只能改 `.tres`（或生成它的 `tools/gen_data.gd`），
> 不允许改逻辑脚本。

---

## 0. 数据是怎么进到游戏里的

```
res://data/**/*.tres
        │  ConfigDB._ready() → reload() 扫盘
        ▼
ConfigDB.items / weapons / characters / enemies / loot_tables / skill_trees /
        projectiles / forest_maps        （全部是 StringName → Resource 的字典）
        │
        ▼
业务代码只通过 get_xxx(id) 取用，取不到会 push_error 并返回 null
```

- 扫盘实现见 `scripts/autoload/config_db.gd::_list_resources()`。
  它专门处理了导出后的 `.remap` 后缀，所以**在导出构建里同样可用**。
- `ConfigDB.reload()` 末尾会跑 `_validate()`，把问题写进 `load_errors`
  并 `push_error`。**启动时的报错就是数据出错了**，别忽略。

### 重新生成全部数据

```powershell
& $GODOT --headless --path E:\GodotProject --script res://tools/gen_data.gd
```

> ⚠️ 重跑会**覆盖**你在编辑器里对 `.tres` 做的手动修改。
> 建议：正式调数值就直接改 `.tres`；结构性新增（新武器/新技能）才改生成器。

### 新增一个 `.tres` 的两种方式

1. **编辑器**：在 `data/<类别>/` 右键 → 新建资源 → 选对应类 → 填 `id` 与字段 → 保存。
2. **代码**：在 `tools/gen_data.gd` 里加一段构造 + `_save(res, "类别", "文件名")`，然后重跑。

两种都要保证：**文件名 == id**。

## 1. ItemData（`scripts/data/item_data.gd`）

所有物品的基类。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | StringName | 全局唯一，snake_case，等于文件名 |
| `display_name` | String | 中文显示名 |
| `description` | String | 说明（支持 BBCode） |
| `icon_sheet` | String | `Atlas.SHEETS` 里的图集名；留空则子类自己实现 `get_icon()` |
| `icon_cell` | Vector2i | 图集内格子坐标 |
| `icon_scale` | float | 图标额外缩放 |
| `item_type` | ItemType | `WEAPON / CONSUMABLE / MATERIAL / GOLD / KEY / CHEST` |
| `rarity` | Rarity | 决定 UI 描边色与掉落权重 |
| `max_stack` | int | 1 = 不可堆叠 |
| `sell_price` | int | 售价 |
| `tags` | PackedStringArray | 供掉落表/技能条件筛选 |

### ConsumableData（子类）
额外字段：`heal_amount / mp_amount / armor_amount / consume_on_use / use_time / sfx_use / fx_color`。

使用入口唯一：`Player.use_consumable(index)` 或 `Player.use_best_potion()`。

## 2. WeaponData（`scripts/data/weapon_data.gd`）

继承 `ItemData`。

### 形态
| 字段 | 说明 |
|---|---|
| `kind` | `MELEE / RANGED / SHOTGUN / BOW / STAFF` |
| `two_handed` | 双手（第二阶段启用） |

### 数值
| 字段 | 说明 |
|---|---|
| `damage` | **单发/单次挥砍**基础伤害（霰弹枪是「单枚弹丸」伤害） |
| `energy_cost` | 每次开火消耗能量（法杖/樱花霰弹枪） |
| `fire_rate` | 射击间隔（秒/发） |
| `magazine` | 弹匣容量，0 = 无弹匣（弓/法杖） |
| `reload_time` | 换弹时间 |
| `projectile_count` | 单次射击弹丸数（霰弹 > 1） |
| `spread_deg` | 散布总角度 |
| `bullet_speed` / `bullet_lifetime` | 弹丸初速 / 存活时间 |
| `knockback` | 击退力度 |
| `crit_bonus` | 额外暴击率 |

### 近战形态
`melee_arc_deg`（扇形角度）、`melee_range`（距离）、`melee_swing_time`（挥砍时长）。

### 实现挂载 ★最关键的两个字段
| 字段 | 说明 |
|---|---|
| `script_path` | 专属实现脚本。**留空 = 第一阶段「只有贴图」的状态**，走默认实现 |
| `projectile_scene` / `projectile_data` | 自定义投射物 |

**分发优先级**（`WeaponRegistry.resolve_script`）：
1. `script_path` 非空且存在 → 用专属脚本
2. 否则 `kind == MELEE` → `WeaponMelee`；其余 → `WeaponRanged`

### 游侠（`ranger`）的第一阶段数值

```
生命 50   护甲 40   能量 80   移速 78
暴击 10%  暴伤 2.0x 手刀 4
护甲：脱战 2.5s 后以 8/s 回复      能量：3/s 自然回复
技能：翻滚（1.20s CD，无耗蓝，0.30s 无敌，之后 0.65s 内下次攻击必暴）
初始：猎弓 + 小治疗药水 + 小能量药水
```

> **数值口径说明**：参考《元气骑士》游侠（生命 5 / 护甲 4 / 能量 80 / 暴击 10 / 手刀 4），
> 本项目按 ARPG 口径把生命与护甲 **×10**，其余保持原比例。
> 这样血条能做精细的百分比显示，同时保留原作的「脆皮高暴击」手感。

> ⚠️ **初始物资只在 `GameState.reset_new_game()` 发放一次**。
> 不要把它写进 `Player._setup_from_game_state()`，否则每次进出大厅都会白送一份。

## 5. LootTable（`scripts/data/loot_table.gd`）★ 第一阶段掉率全在这里

| 组 | 字段 | 说明 |
|---|---|---|
| 抽取次数 | `roll_count` | 从 `entries` 里独立抽取几次 |
| | `empty_weight` | 「空手」权重，与 entries 总权重竞争 |
| | `min_results` / `max_results` | 产出条目数夹取 |
| 必定掉落 | `guaranteed` + `guaranteed_chances` | 逐条独立判定 |
| 随机掉落 | `entries` | 加权随机池 |
| 金币 | `gold_min / gold_max / gold_chance` | |
| **装备掉落** | `weapon_drop_chance` | 出装备的概率 |
| | `weapon_count_range` | 出几件 |
| | `weapon_rarity_weights` | **[白, 绿, 蓝, 橙] 权重** ← 调掉率就改这里 |
| | `extra_weapon_chance` | 额外再出一件的概率 |
| 特殊 | `guarantee_weapon` / `rarity_floor` / `rarity_ceiling` / `luck_influence` | |

### 第一阶段的掉率设计（已实装，见 `LootService.drop_rate_table()`）

| 宝箱 | 归属 | roll 次数 | 空手权重 | 装备概率 | 装备品质分布 | 金币 | 额外 |
|---|---|---|---|---|---|---|---|
| **普通宝箱**<br>`chest_normal` | 小怪 | 2 | 15 | **60%**，1 件 | 白 70% / 绿 25% / 蓝 5% / 橙 0% | 3–10 | 药水/材料 |
| **优秀宝箱**<br>`chest_fine` | 精英怪 | 2 | 4 | **100%**，1 件 +35% 追加 | 绿 45% / 蓝 45% / 橙 10% | 15–35 | 药水/獠牙/卷轴 |
| **稀有宝箱**<br>`chest_rare` | BOSS | 3 | 0 | **100%**，2–3 件 | 蓝 80% / 橙 20% | 60–120 | 大药/碎片/必出钥匙 35% |

**敌人直接掉落**（除宝箱外）：
| 表 | 归属 | 装备概率 | 备注 |
|---|---|---|---|
| `enemy_normal` | 小怪 | 5% | 主要是材料与药水 |
| `enemy_elite` | 精英 | 30% | 2 次抽取 |
| `enemy_boss` | BOSS | 100%，1–2 件 | 4 次抽取 + 40–80 金币 |

### 幸运（Luck）如何影响掉率
`LootService._luck_factor()`：

| 品质 | 系数 |
|---|---|
| 白 | `max(0.15, 1 - luck×0.18)` ← 幸运越高白装越少 |
| 绿 | `1 + luck×0.12` |
| 蓝 | `1 + luck×0.30` |
| 橙 | `1 + luck×0.45` |

幸运来自技能树 `StatKind.LUCK`。
实测（`Validation.tscn` 输出）：`500 次掷骰，出蓝及以上的次数 luck=0 → 约 50，luck=5 → 约 165`。

### 掉落表里的特殊 id
- `&"@random_weapon"` —— 占位符，表示「随机一件武器」，
  配合 `LootEntry.force_rarity` 可指定品质；未指定时默认白装并逐级降级查找。

## 6. SkillTreeData / SkillNodeData（全局技能树）

### SkillNodeData 字段
| 组 | 字段 |
|---|---|
| 标识 | `id / display_name / description / icon_id`（对应 `Atlas.SKILL_ICONS`） |
| 树结构 | `branch` / `grid_position`（面板网格坐标）/ `prerequisites` / `prerequisite_levels` |
| 等级与消耗 | `max_level` / `cost_per_level` / `required_player_level` |
| 效果 | `effects: Array[StatEffect]` / `granted_tags: PackedStringArray` |
| 表现 | `is_keystone`（关键天赋，边框更粗） |

### StatEffect 字段
| 字段 | 说明 |
|---|---|
| `stat` | `GameEnums.StatKind` |
| `per_level` | 每级增量；`is_mult=true` 时是「每级百分比」 |
| `is_mult` | false = 加法修正；true = 乘法修正 |

### 效果如何生效
```
SkillTreeService.unlock()
   → EventBus.skill_tree_changed
   → GameState._on_skill_tree_changed → rebuild_stats()
   → CharacterData.build_stat_block()  ← 角色基础
   → SkillTreeService.apply_to(block)  ← 注入技能树修正
   → block.recalculate()
   → Player.on_stats_rebuilt()         ← 同步上限（保留当前值比例）
```

### 能力标签（granted_tags）★
标签是「技能树影响代码逻辑」的**唯一合法通道**。
需要硬逻辑时，在对应系统 `has_tag()` 判空，**不要在技能节点里挂脚本**。

第一阶段的两个标签：
| 标签 | 效果 | 消费方 |
|---|---|---|
| `double_roll` | 翻滚充能 +1 | `RogueRoll.max_charges()` |
| `cherry_mastery` | 樱花霰弹枪 +1 花瓣、散布收紧 20% | `WeaponCherryShotgun._pellet_count() / _effective_spread()` |

### 第一阶段的全局技能树（22 节点 / 4 分支 / 7×5 网格）

| 分支 | 节点（id / 名称 / 效果） |
|---|---|
| **生存** `vitality` | `v_hp1` 强健体魄（生命 +8/级）、`v_hp2` 生命涌动（+14/级）、`v_armor1` 铁壁（护甲 +6/级）、`v_armor2` 护甲强化（回甲 +1.6/级，延迟 −0.25s/级）、`v_regen` 再生之息（+0.6 生命/s 每级） |
| **进攻** `offense` | `o_dmg1` 锋利（伤害 +5%/级）、`o_crit1` 精准打击（暴击 +3%/级）、`o_dmg2` 战意（+7%/级）、`o_crit2` 致命一击（暴伤 +18%/级）、`o_melee` 手刀专精（+3/级）、**`o_keystone` 狂怒之心**（伤害 +15%、暴击 +5%） |
| **敏捷** `mobility` | `m_speed1` 疾风步（移速 +4/级）、`m_reload` 快速换弹（+10%/级）、`m_fire` 急速射击（射速 +8%/级）、`m_roll1` 翻滚精通（冷却 −10%/级）、`m_roll2` 翻滚距离（+12px/级）、**`m_keystone` 双翻滚**（标签 `double_roll`） |
| **幸运** `fortune` | `f_luck1` 幸运（+0.8/级）、`f_pickup` 磁力吸附（拾取范围 +14/级）、`f_mp` 能量涌动（上限 +12/级、回复 +0.9/s 每级）、**`f_keystone` 贪婪之心**（幸运 +2.5）、**`f_cherry` 樱花精通**（标签 `cherry_mastery`） |

## 9. 「加内容」标准流程（照抄即可）

### 9.1 加一个消耗品

1. 在 `tools/gen_data.gd::_gen_items()` 加一行：
   ```gdscript
   _item_consumable(&"mp_potion_huge", "超大能量药水", GameEnums.Rarity.RARE,
       Vector2i(4, 3), 0.0, 200.0, "一口气回满能量。", 90)
   ```
2. 重跑 `gen_data.gd`。
3. 重跑 `Validation.tscn`（会自动检查图集格子非空、掉落表引用有效）。

### 9.2 加一把「只有贴图」的武器

1. 在 `assets/sprites/weapons.png` 的空格里画好（或改 `gen_pixel_assets.gd` 重生成）。
2. 在 `Atlas.WEAPON_FRAMES` 登记 `id → Vector2i(列, 行)`。
3. 在 `gen_data.gd::_gen_weapons()` 加一条 `_weapon(...)`。
4. 重跑 `gen_data.gd` + `--import` + 验证。
5. 注意：品质计数必须仍然满足「每品质 3 把通用武器」。

### 9.3 给武器写专属实现

1. 新建 `scripts/weapons/<武器id>.gd`，`extends WeaponBase`，实现 `_do_fire()`。
2. 在 `gen_data.gd` 里把该武器的 `script_path` 指向它（或在编辑器里改 `.tres`）。
3. 把它从「通用武器」里排除后仍满足 3 把/品质（必要时补一把新的通用武器）。
4. 参考 [07_樱花霰弹枪实现说明.md](07_樱花霰弹枪实现说明.md)。

### 9.4 加一个敌人

1. 确认已有贴图（`Atlas.ENEMY_SHEETS` 里有 key）。没有就先画。
2. 在 `gen_data.gd::_gen_enemies()` 加一条 `_enemy(...)`。
3. 新行为 → 在 `Enemy._tick_behavior()` 加分支
   **并同步更新 `tools/validation.gd::_check_data_integrity()` 的 `valid_behaviors`**。
4. 重跑生成 + 验证 + 冒烟。

### 9.5 加一个技能节点

在 `gen_data.gd::_gen_skill_tree()` 里加一条 `_skill(...)`，
注意 `prerequisites` 只能引用已存在的 id，且不能成环（`ConfigDB._validate()` 会检测）。
