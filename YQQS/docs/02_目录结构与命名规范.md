### 判断「这个东西该放哪」的快速规则

| 如果它是… | 放 |
|---|---|
| 一个数值 / 概率 / 配置 | `data/**/*.tres` |
| 一个类的**定义**（Resource 形状） | `scripts/data/` |
| 一个全局的唯一服务 | `scripts/autoload/` |
| 一个可以被多个实体挂的**零件** | `scripts/components/` |
| 一个**具体的**游戏对象（玩家/敌人/武器/子弹） | `scripts/entities/`、`scripts/weapons/`、`scripts/projectiles/` |
| 一个界面 | `scripts/ui/` + `scenes/ui/` |
| 生成器 / 校验器 / 一次性脚本 | `tools/` |

## 2. 命名规范

### 2.1 文件与目录

| 类型 | 规范 | 例子 |
|---|---|---|
| 目录 | `snake_case`，**只用单数** | `scripts/components/`、`data/weapons/` |
| GDScript | `snake_case.gd`，与主类名一一对应 | `vitals_component.gd` ← `class_name VitalsComponent` |
| 场景 | `PascalCase.tscn`，与根节点名一致 | `Player.tscn`、`ForestLevel.tscn` |
| Resource | `snake_case.tres`，**与 `id` 字段一致** | `cherry_shotgun.tres`、`forest_config.tres` |
| 图集 | 语义化 + 网格 | `player_ranger.png`、`enemy_goblin.png`、`tileset_forest.png` |
| 测试/工具场景 | `PascalCase.tscn` | `Validation.tscn`、`SmokeTest.tscn` |

> **强约束**：`.tres` 的文件名必须等于资源里的 `id`。
> `ConfigDB` 的校验会检查重复 id，但改文件名不改 id 会造成「看起来存在但取不到」。

### 2.2 标识符

| 类型 | 规范 | 例子 |
|---|---|---|
| 类名 | `PascalCase` | `WeaponCherryShotgun` |
| 常量 | `SCREAMING_SNAKE` | `BASE_PELLETS`、`ROLL_TIME` |
| 成员变量 | `snake_case` | `fire_rate`、`_cooldown` |
| 私有变量 | 前导下划线 | `_hit_targets`、`_rng` |
| 函数 | `snake_case`，动词开头 | `apply_damage`、`try_fire` |
| 私有函数 | 前导下划线 | `_on_vitals_died` |
| 虚函数（子类覆写） | 前导下划线 | `_do_fire`、`_tick_behavior` |
| 信号 | `主语_过去式` | `enemy_died`、`chest_opened` |
| 资源 id | `snake_case` | `&"cherry_shotgun"`、`&"goblin_priest"` |
| 节点名 | `PascalCase` | `EntityRoot`、`WeaponPivot` |

### 2.3 字符串键的约定

| 用途 | 类型 | 例子 |
|---|---|---|
| 物品/武器/敌人/掉落表/技能 id | `StringName`（`&"..."`） | `&"hp_potion_small"` |
| group 名 | `StringName` | `&"enemies"`、`&"interactable"`、`&"fx_root"` |
| 行为类型 / 运动模式 | `StringName` | `&"chaser"` → `&"chase_melee"`、`&"bounce"` |
| UI 面板 id | `StringName` | `&"inventory"`、`&"skill_tree"` |

**用 `StringName` 而不是 `String`**：比较与哈希更快，且 Godot 会做驻留，
是 Godot 里表示「键」的惯用类型。

## 3. 组（Group）登记表

运行时查找靠 group，以下是**全部**使用中的 group，新增必须登记在此：

| group | 谁加入 | 谁查询 | 用途 |
|---|---|---|---|
| `players` / `player` | `Player` | `Enemy._update_target`、`PickupBase._find_player` | 单例玩家 |
| `enemies` | `Enemy` | 投射物追踪、`NodeUtils.nearest_in_group` | 敌人集合 |
| `pickups` | `PickupBase` | 调试 | 掉落物 |
| `interactable` | `Interactable` | `Player._find_interactable` | 可交互物 |
| `fx_root` | `ForestLevel` / `Lobby` | `CombatFx.fx_parent` | 特效挂载点 |
| `entity_root` | 同上 | `Enemy._entity_parent` | 敌人/掉落挂载点 |
| `projectile_root` | 同上 | `WeaponBase._projectile_parent` | 投射物挂载点 |
| `pickup_root` | 同上 | `LootService` | 掉落物挂载点 |

> **关卡必须注册这四个 `*_root`**，否则 `CombatFx` 与掉落物会挂错父节点
> （挂在实体上 → 实体被销毁时特效/掉落一起消失）。

## 5. 代码风格

- **缩进**：Tab（Godot 默认）。`gdlint`/`gdformat` 兼容。
- **类型标注**：公开 API 必须标注参数与返回类型；局部变量能用 `:=` 推断就用。
  ⚠️ Godot 4.7 默认把「从 Variant 推断类型」当**错误**（`Warning treated as error`），
  所以从 Dictionary / `get()` 取值时**必须**显式写类型，例如：
  ```gdscript
  var col: Color = BRANCH_COLORS.get(branch, Color.WHITE)   # ← 必须写 : Color
  var sp = holder.get("sprite")                             # ← 不能写 :=
  ```
- **注释语言**：中文。每个文件的头部必须有 `##` 文档注释，说明**这个文件是什么、
  哪些事情归它管、哪些不归它管**。
- **框架约束块**：公共基类/关键系统必须带 `## 【框架约束 · 必读】` 段落，
  写明「必须怎么做 / 禁止怎么做」。这是本项目的核心工程习惯。
- **禁止魔法数字**：抽成 `const` 或 `.tres` 字段并写注释。
- **`_ready` 里不做重活**：耗时操作（地图生成、扫盘）统一由 `Boot` / `ForestLevel`
  这类明确的入口触发。

## 6. 场景（.tscn）的两种形态

本项目**只有两种**场景：

### A. 实体场景 —— 手写 `.tscn`，结构稳定

```gdscript
# Player.tscn 的节点骨架（声明式，方便在编辑器里看）
Player (CharacterBody2D)   [player.gd]
├── Shadow (Sprite2D)
├── Sprite (Sprite2D)
├── CollisionShape2D
├── Vitals (Node)          [vitals_component.gd]
├── Hurtbox (Area2D)       [hurtbox_component.gd]
│   └── CollisionShape2D
├── MeleeHitbox (Area2D)   [hitbox_component.gd]
│   └── CollisionShape2D
├── WeaponPivot (Node2D)   ← 武器运行时挂在这里
└── Camera2D
```

**子节点的名字是契约**：脚本用 `find_child("Hurtbox")` 等按名查找，
改名要同步改脚本（或用 `@export` 的 NodePath 覆盖）。

### B. UI / 关卡 / 工具场景 —— 极简 `.tscn`，内容代码生成

```
InventoryPanel (Control)   [inventory_panel.gd]
```
就这一个节点。所有子控件在 `_ready()` 里用 `UIKit` 造出来。原因见 06 号文档。

## 7. 提交前自检清单

改完代码，按顺序做：

```powershell
$GODOT = "E:\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe"

# 1) 加了新 class_name / 新 .tres 后，先重建类缓存与导入
& $GODOT --headless --path E:\GodotProject --import

# 2) 静态自检（必须 0 错误）
& $GODOT --headless --path E:\GodotProject res://tools/Validation.tscn; "exit=$LASTEXITCODE"

# 3) 运行时冒烟（必须 0 错误）
& $GODOT --headless --path E:\GodotProject res://tools/SmokeTest.tscn; "exit=$LASTEXITCODE"
```

> `--import` 这一步**经常被忘**。新增 `class_name` 后不 import，会看到
> 「Identifier "XxxData" not declared in the current scope」这种假性编译错误。
