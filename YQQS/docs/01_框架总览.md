# 01 · 框架总览

> 本文是**改代码之前必读**的那一篇。读完你应该能回答：
> 「我要加一个功能，应该动哪些文件？数据从哪来？谁通知谁？」

---

## 1. 技术选型与理由

| 决策 | 选择 | 理由 / 备选为什么不行 |
|---|---|---|
| 引擎 | Godot 4.7.2 | 2D 原生、程序化生成友好、无外部依赖 |
| 语言 | **GDScript**（不用 C#） | 项目是 mono 版引擎，但脚本全用 GDScript：无需编译步骤、迭代快、热重载好 |
| 2.5D 方案 | **2D 俯视 + Y 排序 + 伪高度轴**（不用真 3D） | 见 §3。像素风下 3D 反而更难保证像素对齐 |
| 逻辑分辨率 | **480×270**，整数倍放大到 1440×810 | 16px 图块 → 一屏 30×17 格，视野合适；整数倍保证像素完美 |
| 拉伸模式 | `canvas_items` + `integer` | 见 §3.4。这是「精灵像素完美 + 中文清晰」的唯一组合 |
| 数据 | `.tres` Resource（不是 JSON/CSV） | 编辑器可视化编辑 + 类型安全 + 可被 `@export` 引用 |
| UI | **代码构建**（`.tscn` 只放一个挂脚本的根节点） | 见 06 号文档 |
| 随机 | 全部走 `RandomNumberGenerator` | 可播种复现。**禁止** `randf()` / `randi()` |

## 2. 分层架构

```
┌─────────────────────────────────────────────────────────────────┐

│          VFX (CombatFx / HitSpark / FloatingLabel)               │
└───────────────▲─────────────────────────────────┬───────────────┘
                │ 订阅 EventBus 信号               │ 调用公开方法
┌───────────────┴─────────────────────────────────▼───────────────┐
│  系统层  RunManager(单局)  LootService(掉落/宝箱)                 │
│          SkillTreeService(技能树)  WarehouseService(仓库)         │
│          SaveSystem(存档)  SceneRouter(场景/UI)  AudioManager     │
│          ConfigDB(只读数据源)                                     │
└───────────────▲─────────────────────────────────┬───────────────┘
                │                                 │
┌───────────────┴─────────────────────────────────▼───────────────┐

│                 └─ Enemy(数据驱动 AI)                            │
│          WeaponBase ─ WeaponRanged / WeaponMelee / CherryShotgun │
│          Projectile      PickupBase / Chest / Portal             │
└───────────────▲─────────────────────────────────┬───────────────┘
                │                                 │
┌───────────────┴─────────────────────────────────▼───────────────┐
│  组件层  VitalsComponent(血/甲/蓝)  HitboxComponent  HurtboxComponent │
│          HealthBar  StatBlock  DamageInfo  Inventory             │
└───────────────▲─────────────────────────────────┬───────────────┘
                │                                 │
┌───────────────┴─────────────────────────────────▼───────────────┐
│  数据层  .tres：ItemData / WeaponData / EnemyData / CharacterData │
│          LootTable / SkillTreeData / ProjectileData / ForestMapConfig │
│          GameEnums(枚举) / Atlas(图集索引) / Layers(物理层)        │
└─────────────────────────────────────────────────────────────────┘
```

**依赖方向永远向下**：上层可以调下层，下层**绝不能**反向依赖。
唯一的例外是 `EventBus` —— 它是横向的、谁都能发谁都能收。

## 3. 2.5D 像素表现约定（最容易踩坑的一节）

### 3.1 坐标系

- 逻辑坐标只有 **x / y** 两轴，**没有真实 z**。
- `y` 越大 = 越靠近镜头（越「前」）。
- 所有 Actor 的**碰撞体原点在脚下（地面平面）**，精灵通过偏移画在原点上方。

### 3.2 排序：Y 排序

关卡的实体容器 `EntityRoot` 开启 `y_sort_enabled`，节点按 `position.y` 排序。
**效果**：走到树后面会被树挡住，走到树前面会挡住树。

```gdscript
# ForestLevel._build_nodes() 里：
entity_root = Node2D.new()
entity_root.y_sort_enabled = true      # ← 2.5D 的全部秘密
```

**禁止**用 `z_index` 做前后遮挡（会和 y_sort 打架）。
`z_index` 只允许用于两类东西：
- 永远在最上层的：特效容器（`FxRoot`，z=20）、飘字（`FloatingLabel`，z=200）
- 相对父节点的微调：武器朝上时 `w.z_index = -1`（画在角色身后）

### 3.3 高度：`Actor.z_height`

需要「离地」时（跳跃、翻滚、飞行、击飞），改 `z_height`：

```gdscript
actor.set_z_height(12.0)   # 精灵上移 12px，影子缩小变淡
actor.set_z_height(0.0)    # 落地
```

`Actor._update_visuals()` 统一处理：

```gdscript
sprite.position.y = sprite_offset_y - z_height        # 精灵上移
shadow.scale = base * clampf(1 - z_height/48, .25, 1) # 影子缩小
```

**这就是本项目 2.5D 的全部实现，没有 3D 节点。**

### 3.4 分辨率与文字

```
viewport       480 × 270
window override 1440 × 810   (整数倍 3x)
stretch/mode   canvas_items   ← 关键
stretch/aspect keep
scale_mode     integer
```

**为什么不用 `viewport` 模式**：`viewport` 会把 UI 文字也按 480×270 渲染再整体放大，
中文会糊成一团肉。`canvas_items` 模式下精灵仍按最近邻整数放大（像素完美），
而字体在放大后的分辨率上渲染（文字清晰）。这是本项目的最优解，**不要改**。

### 3.5 图集与切图

- 所有精灵来自 `assets/sprites/*.png`，图集布局登记在 `scripts/core/atlas.gd`。
- 代码里**禁止**出现裸 PNG 路径或手写 `Rect2` 切图，一律 `Atlas.frame("图集名", 列, 行)`。
- 项目已设 `default_texture_filter = 0`（最近邻）；`AtlasTexture` 额外设 `filter_clip = true`
  防止相邻格子渗色。

## 4. 十个自动加载单例（Autoload）

启动顺序 = 依赖顺序，**不要随意调换**（见 `tools/setup_project.gd` 的 `AUTOLOADS`）。

| # | 名称 | 职责 | 关键 API |
|---|---|---|---|
| 1 | `EventBus` | 全局信号总线，**唯一的跨系统通信通道** | 见 §5 |
| 2 | `ConfigDB` | 启动扫描 `res://data/**` 加载全部 `.tres`，并做完整性校验 | `get_item / get_weapon / get_enemy / get_loot_table / get_skill_tree / get_forest_config / all_weapons` |
| 3 | `SaveSystem` | JSON 存档（两段式写入 + 版本迁移 + 60s 自动存） | `save_game / load_game / load_or_new / new_game / list_slots` |
| 4 | `GameState` | 玩家档案唯一权威：等级/经验/金币/背包/已解锁角色/**已装备武器** | `select_character / add_gold / add_xp / rebuild_stats / get_stat` |
| 5 | `SceneRouter` | 场景切换（带淡入淡出）+ UI 面板栈 + 暂停 | `go_to / open_panel / toggle_panel / set_paused / get_ui_root` |
| 6 | `AudioManager` | 音效池 + BGM 交叉淡入 + 音量设置持久化 | `play_sfx / play_sfx_2d / play_bgm` |
| 7 | `SkillTreeService` | 全局技能树：加点、洗点、效果注入、能力标签 | `unlock / can_unlock / apply_to / has_tag / get_level` |
| 8 | `WarehouseService` | 仓库（账号级持久 60 格） | `deposit_from_inventory / withdraw_to_inventory / sort_store` |
| 9 | `LootService` | 掉落与宝箱：品质掷骰、掉落表抽取、宝箱/掉落物实例化 | `roll_table / roll_rarity / open_chest / handle_enemy_death / spawn_chest` |
| 10 | `RunManager` | 单局生命周期 + 种子 + 存活敌人登记 | `start_run / end_run / notify_enemy_spawned / alive_enemy_count` |

> **注意**：Godot 的自动加载单例是在**主循环启动后**才注册为全局标识符的。
> 因此任何用 `--script` 跑的脚本都**无法**引用 `EventBus` 等名字（会假性报「Identifier not found」）。
> 这就是为什么校验器 `Validation.tscn` / `SmokeTest.tscn` 是**场景**而不是 `--script`。

## 5. EventBus 信号表（谁发 → 谁收）

新增信号必须写在 `scripts/autoload/event_bus.gd` 里并补注释，**禁止**在别处 `connect("字符串")`。

### 玩家
| 信号 | 发送方 | 接收方 |
|---|---|---|
| `player_spawned(player)` | `Player._on_actor_ready` | HUD、RunManager |
| `player_died()` | `Player.die` | RunManager、ForestLevel |
| `player_hp_changed / armor / mp (cur, max)` | `VitalsComponent` | HUD |
| `player_level_changed(level, xp, next)` | `GameState.add_xp/from_dict` | HUD、Lobby |
| `gold_changed(amount)` | `GameState.add_gold` | HUD、Lobby |

### 战斗
| 信号 | 发送方 | 接收方 |
|---|---|---|
| `damage_dealt(target, info)` | `HurtboxComponent` | 飘字/特效 |
| `enemy_died(enemy, tier, pos)` | `Enemy._on_death` | `RunManager`、`ForestLevel` |
| `hitstop_requested(duration)` | `VitalsComponent` | 未来的时间缩放控制器 |
| `screen_shake_requested(strength, duration)` | 武器/受击 | 相机 |

### 掉落 / 仓库 / 技能树
| 信号 | 发送方 | 接收方 |
|---|---|---|
| `inventory_changed()` | `Inventory._emit_changed` | 背包面板 |
| `warehouse_changed()` | `WarehouseService` | 仓库面板 |
| `chest_spawned / chest_opened` | `LootService` | HUD、RunManager |
| `loot_dropped(item, pos)` | `LootService` | HUD |
| `item_picked_up(item, pos)` | `ItemPickup._collect` | HUD |
| `skill_points_changed(points)` / `skill_tree_changed()` | `SkillTreeService` | 技能树面板、`GameState` |
| `skill_unlocked(id, level)` | `SkillTreeService.unlock` | 技能树面板 |

### 关卡 / UI
| 信号 | 发送方 | 接收方 |
|---|---|---|
| `run_started(seed, floor)` / `run_ended(victory)` | `RunManager` | HUD |
| `map_generated(level, graph)` | `ForestLevel._generate` | 调试面板 |

| `toast(text, color)` | 任意系统 | HUD 提示条 |

## 6. 一条典型的完整数据流

以「玩家用樱花霰弹枪打中史莱姆」为例，看清楚每一步谁负责：

```
① 输入       Player._handle_actions 读到 fire 按下
② 武器       Player._try_attack → WeaponBase.try_fire()
③ 资源检查   can_fire() 查冷却 / 弹药 / 能量；consume_shot() 扣弹与能量
④ 数值       WeaponCherryShotgun._do_fire()
               roll_crit()  ← 会先问 Player.consume_guaranteed_crit()（游侠翻滚联动）
               build_damage() → DamageInfo(amount, crit, faction=PLAYER)
⑤ 弹丸       生成 5 个 Projectile，每个带一份 DamageInfo 模板
⑥ 碰撞       Projectile._on_area_entered 命中 Enemy 的 Hurtbox
⑦ 结算       HurtboxComponent.receive_hit(info)
               ② 阵营判定（同阵营免伤）③ 无敌判定
               ④ VitalsComponent.apply_damage()：
                    伤害减免 → 护甲吸收 → 生命扣除 → i-frame → 广播 damaged
⑧ 表现       CombatFx.damage_number() 飘字 / hit_spark 火花 / 顿帧 / 屏幕震动
⑨ 死亡       VitalsComponent.died → Enemy._on_death
               → LootService.handle_enemy_death() 掷宝箱/金币/直接掉落
               → EventBus.enemy_died → RunManager 计数 + ForestLevel 判房清
⑩ UI         HUD 通过 EventBus 被动刷新（全程不轮询）
```

**记住这个链路**，任何战斗相关的改动都要能对应到其中某一步。

## 7. 「我要加 X」索引

|---|---|---|
| 加一个物品/药水/材料 | 跑 `tools/gen_data.gd` 或在编辑器里新建 `.tres` 放 `data/items/` | 03 |

## 8. 已知约束与「不要做」清单

- ❌ 不要在代码里硬编码任何数值（伤害、掉率、房间尺寸、技能效果）。
- ❌ 不要用 `randf()` / `randi()`，一律 `RandomNumberGenerator`。
- ❌ 不要用 `Node2D.z_index` 做前后遮挡（用 y_sort）。
- ❌ 不要直接改 `vitals.hp` / `inventory.slots` / `GameState.gold`，
  一律走 `apply_damage` / `Inventory.*` / `add_gold`。
- ❌ 不要让 UI 轮询游戏状态，订阅 EventBus。
- ❌ 不要用 `--script` 跑需要自动加载的脚本（会假性编译失败）。
- ❌ 不要改 `project.godot` 的 `stretch/mode`（会导致中文糊）。
- ⚠️ `Enemy` / `Chest` / `ItemPickup` 的 `configure()` **必须在 `add_child()` 之前**调用，
  因为 `_ready()` 就需要数据。
