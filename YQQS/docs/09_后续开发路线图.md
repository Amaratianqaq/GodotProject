## 优先级 0 · 立刻能做的收尾（每项 < 1 小时）

### 0.1 相机屏幕震动（约 30 分钟）
现在 `EventBus.screen_shake_requested` 有广播但**没有消费者** —— 打击感白送了一半。

```gdscript
# scripts/components/camera_shake.gd
class_name CameraShake
extends Node

@export var target_path: NodePath          # 指向 Camera2D
var _strength := 0.0
var _decay := 8.0
var _camera: Camera2D = null
var _base_offset := Vector2.ZERO

func _ready() -> void:
    _camera = get_node_or_null(target_path) as Camera2D
    if _camera:
        _base_offset = _camera.offset
    EventBus.screen_shake_requested.connect(_on_shake)

func _on_shake(strength: float, _duration: float) -> void:
    _strength = maxf(_strength, strength)

func _process(delta: float) -> void:
    if _camera == null:
        return
    if _strength <= 0.001:
        if _camera.offset != _base_offset:
            _camera.offset = _base_offset
        return
    _strength = maxf(0.0, _strength - _decay * delta)
    _camera.offset = _base_offset + Vector2(
        randf_range(-_strength, _strength),
        randf_range(-_strength, _strength)
    )
```
挂到 `Player.tscn` 的 `Camera2D` 的父级（或直接把逻辑并进 `Player`）。
注意用 `_physics_process` 或 `process_priority` 保证在相机跟随之后应用。

### 0.2 接入音频资源（约 30 分钟 + 找资源的时间）
所有音效路径**已经配好**，`AudioManager` 对不存在的文件静默跳过。放文件即生效：

```
assets/audio/sfx/  shoot.wav  reload.wav  empty.wav  coin.wav  pickup.wav
                   roll.wav   hurt.wav    enemy_attack.wav  enemy_die.wav

                   petal_hit.wav  drink.wav   room_clear.wav
assets/audio/bgm/  lobby.ogg  forest.ogg
```
然后 `Validation.tscn` 会把这些路径的有效性纳入检查（可选加一条）。

### 0.3 修「走廊卡怪」
目前敌人是**直线追击**，遇到树会卡住。这是当前最影响体验的问题。

三个层次的方案，按成本递增：
1. **最便宜**：装饰时**不在走廊里放有碰撞的树**（改 `ForestLevel._decorate`）
2. **中等**：加 `NavigationRegion2D`，`Enemy` 用 `NavigationAgent2D` 走路径
3. **最好**：2 + 敌人在被卡住 1.5s 后重新计算路径（防动态阻塞）

建议先做 1 止血，第二阶段做 2。

### 0.4 BOSS 血条加护甲段
`Hud._update_boss_live()` 目前只接了 `ratio_hp()`。
`StatBar` 已经支持 `show_ghost`，加一层护甲用第二条 `StatBar` 叠上去即可。

## 优先级 1 · 第二阶段主线（内容量最大）

### 1.1 实装 12 把品质武器的专属机制 ★
这是需求里明确写的「代码实现后续添加」，也是数值手感的主力。

做法完全模板化（见 [07 号文档](07_樱花霰弹枪实现说明.md) §5）：
1. 新建 `scripts/weapons/<id>.gd`，`extends WeaponBase`，实现 `_do_fire()`
2. `data/weapons/<id>.tres` 的 `script_path` 指向它
3. **补一把通用武器**保持「每品质 3 把通用武器」的校验规则
4. 跑 `--import` → `Validation.tscn` → `SmokeTest.tscn`

**建议先做的 4 把**（机制差异最大、最有教学价值）：

| 武器 | 建议机制 |
|---|---|
| `flame_brand` 烈焰之刃 | 命中附加 3 秒燃烧 DoT（见 07 号文档的完整示例代码） |
| `storm_crossbow` 风暴弩 | 三连弩矢命中同一目标时叠加「感电」，第 3 发额外雷击 |
| `arcane_staff` 秘法法杖 | 秘法弹命中后分裂为 3 枚小弹（参考 `homing` 投射物） |
| `battle_axe` 战斧 | 蓄力重击：按住左键蓄力，松手造成范围震荡波 |

## 优先级 3 · 技术债 / 架构重构

> **原则：不提前抽象。** 下面每一条都标了「什么时候必须做」。
> 在触发条件到来之前，保持现状是**更优选择**。

| 技术债 | 什么时候必须做 | 怎么还 |
|---|---|---|
| `ForestLevel` 里混了地表选择/装饰工厂/BOSS 选择 | **出现第二张地图时** | 抽 `LevelTheme` 资源（图集、地表映射、装饰工厂列表、BOSS id、密度默认值），`ForestLevel` 变成通用 `DungeonLevel` |

| `CombatFx` 是静态类（`_floating_count` 是 static var） | 需要多世界/分屏时 | 改成挂在场景里的单例节点 |
| `WeaponBase` 里同时有远程与近战的辅助方法 | 加第 3 种武器形态时 | 拆 `RangedWeaponBase` / `MeleeWeaponBase` |

## 每阶段收尾必做的三件事

```powershell
$GODOT = "E:\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe"

# 1) 新增 class_name 后必须重建缓存
& $GODOT --headless --path E:\GodotProject --import

# 2) 静态自检
& $GODOT --headless --path E:\GodotProject res://tools/Validation.tscn; "exit=$LASTEXITCODE"

# 3) 运行时冒烟
& $GODOT --headless --path E:\GodotProject res://tools/SmokeTest.tscn; "exit=$LASTEXITCODE"
```

并且：**每加一个新系统，就在 `Validation.tscn` 或 `SmokeTest.tscn` 里加一条断言。**
这两个文件是本项目的安全网 —— 它们让「改完不知道有没有改坏」这件事不再靠人肉点击。
